# Changelog

All breaking API changes to this project will be documented in this file.

## [Unreleased]

### Added

- [kyo-data] `Glob`: a compiled, platform-independent pattern for matching slash-separated paths, with a `glob"..."` literal interpolator
- [kyo-data] `OrderedDict[K, V]`: an immutable map that iterates in insertion order
- [kyo-data] `OrderedDictBuilder[K, V]`: build an `OrderedDict` from repeated adds
- [kyo-schema] `Schema.stringOrderedDictSchema` and `Schema.orderedDictSchema`: derive a `Schema` for a case class with an `OrderedDict` field
- [kyo-core] `Fiber.use`: use a forked fiber within a function and clean it up
- [kyo-core] `Fiber.initUnscoped`: fork a fiber without guaranteeing cleanup (formerly `Fiber.init`)
- [kyo-system] `Path.tailBytes`: follow a file at the byte level, starting from the beginning, the end, or a recorded offset
- [kyo-system] `Path.Origin`: where a byte-level read begins (`Start`, `End`, `Offset`)
- [kyo-core] `Stream.fromInputStream`: stream a `java.io.InputStream`'s bytes, closed with the enclosing `Scope`
- [kyo-schema] `RecordDecodeException`: decode failure for one record in a multi-record input, carrying its index and byte offset
- [kyo-schema-json] `Json.Lines`: pure JSONL/NDJSON framing (`Framer`, `Pending`, `Line`, `Framed`) plus `decodeAll`, `decodeAllBytes`, `decodeAllBytesResults`, `encodeAll`, `encodeAllBytes`, `encodeLine`
- [kyo-schema-json] `Jsonl`: streaming JSONL/NDJSON over files and byte streams with `read`, `watch`, `pipe`, `encode`, `write`, `append`, and per-record error recovery through the `Results` variants
- [kyo-combinators] `.forkUsing`: apply `Fiber.use`
- [kyo-logging-jpl] `kyo.JavaLog`: bridge `Log` to Java platform logging a.k.a. `System.Logger`
- [kyo-logging-slf4j] `kyo.SLF4JLog`: bridge `Log` to SLF4J 2.0 API
- [kyo-system] `Stream.writeTo` and `Stream.writeLinesTo`: `append` and `createFolders` parameters, matching the `Path` write methods. `append = true` adds to the end of an existing file and leaves that file in place when the stream fails.
- [kyo-system] `FileWriteStalledException(path, remaining)`: a `FileWriteException` reporting a write that consumed none of the bytes it was offered, with the unwritten count as a `ByteSize`
- [kyo-sql] `Sql.from`, `Sql.insert`, `Sql.update` and `Sql.delete`: a `schemaName` parameter beside `tableName`, rendering the two as separately quoted identifiers (`"app"."invoice"`). Both are literals, so a qualified statement still folds at compile time.
- [kyo-sql-postgres] `PostgresConfig.searchPath`: the schemas an unqualified name resolves against, sent in the startup packet so every pooled connection agrees and `SqlClient.reset` restores it.
- [kyo-sql-sqlite] `SqliteAttach`: databases attached to every connection the client opens, so a schema-qualified name resolves on all of them.
- [kyo-slack] `SlackApiException`: the category for Slack's `{"ok":false}` answers, exposing `method`, `code` and Slack's `messages`, with a leaf per code a caller can act on (`SlackChannelNotFoundException`, `SlackMissingScopeException` with its `needed` and `provided` scopes, `SlackInvalidAuthException`, ...) on the operations whose Slack documentation lists it, and `SlackOtherApiException` for any other code
- [kyo-slack] `SlackUnexpectedStatusException(method, status)`: a non-2xx answer with no Slack body
- [kyo-slack] `SlackLinkDisabledException`: Slack disabled the Socket Mode link. An `apps.connections.open` answer without a url is a `SlackDecodeException` at `url`
- [kyo-slack] `SlackInvalidRawBlockException`, `SlackInvalidConfigException`, `SlackInvalidTokenException` and `SlackInvalidMethodException`: panics for a `SlackBlock.Raw` that is not an RFC 8259 JSON object, a `SlackConfig` setting out of range, a token not of Slack's documented shape, and a `SlackMethod` name with a character other than ASCII letters, digits, `.` and `_`, or of only dots
- [kyo-slack] `Slack.let(config)(v)`: provide a client with no Socket Mode connection to `v`, released when `v` ends, for the Web API and `response_url` verbs outside a receive loop
- [kyo-slack] `Slack.use(client)(v)` and `Slack.receive(handler)`: provide a client from `Slack.init` to a computation, and run the receive loop on the provided client
- [kyo-slack] `SlackEnvelope.Acknowledged` and `SlackEnvelope.Plain`: the envelopes grouped by the answer they take, so a handler's fallback arms are `case _: SlackEnvelope.Acknowledged => SlackAck.Ack` and `case _: SlackEnvelope.Plain => Kyo.unit`
- [kyo-slack] `SlackMethod`: a validated Web API method name, taken by `Slack.custom`
- [kyo-slack] `SlackConfig.baseUrl`, `requestTimeout`, `connectTimeout` and `maxResponseLength`: the Web API base (default `https://slack.com/api`), the request and connect bounds (default `10.seconds` each), and the largest answer read (default `16.mb`)
- [kyo-slack] `SlackRefusedUrlException(method)`: a `response_url`, or the Socket Mode url `apps.connections.open` answered, that is not an absolute url of its scheme on a host, refused before anything is sent
- [kyo-slack] `SlackInitFailure`, `SlackRunFailure`, `SlackReceiveFailure`, `SlackAuthTestFailure`, `SlackChatPostMessageFailure`, `SlackChatPostEphemeralFailure`, `SlackChatUpdateFailure`, `SlackViewsOpenFailure`, `SlackViewsUpdateFailure`, `SlackViewsPublishFailure` and `SlackCustomFailure`: one sealed trait per operation, extending `SlackException`, carried by every leaf that operation can fail with
- [kyo-slack] `Slack.initUnscoped`: open a Socket Mode connection that only `Slack.close` ends, for a connection whose lifetime no `Scope` describes
- [kyo-slack] `SlackRawJson`: the raw JSON of a payload the module does not model, readable through `value` and rendered by its length only
- [kyo-slack] `Slack.respondEphemeral`, `Slack.respondInChannel`, `Slack.replaceOriginal` and `Slack.deleteOriginal`: answer a command or interaction later through its `response_url`, with a `SlackReply` (text and optional blocks), each with its own failure trait (`SlackRespondEphemeralFailure`, ...)

### Removed

- [kyo-combinators] `.forkScoped`: changed to `.fork`
- [kyo-core] `LogPlatformSpecific.Unsafe.SLF4J`: removed from JVM module, see above
- [kyo-slack] `SlackHandshakeException`: BREAKING. A failed `apps.connections.open` is now the leaf for what failed (the transport, a Slack code, a decode failure, a missing or refused url), and a Web API call where no client is provided does not compile, since `Env[Slack]` is on its row; match `SlackInitFailure` where `SlackHandshakeException` was matched
- [kyo-slack] `conn.receive` and `conn.close` on a `Slack` connection: BREAKING. `Slack` is a client value with no members a caller calls; run `Slack.use(client)(Slack.receive(handler))` and `Slack.close(client)`
- [kyo-slack] `SlackWebApiException`: BREAKING. Replaced by the `SlackApiException` category and its leaves; match `SlackApiException` and read `code` where `error` was read
- [kyo-slack] `SlackTerminalException`: BREAKING. Renamed to `SlackLinkDisabledException`
- [kyo-slack] `SlackAck.BlockActionsResponse`: BREAKING. The engine POSTed its message after the ack, inside the receive loop, so the next envelope waited on Slack's answer, and a failure could only be logged. Return `SlackAck.Ack` and call `Slack.replaceOriginal` or `Slack.respondEphemeral` with the interaction's `responseUrl`, forked when it can outlast the ack deadline; its failure is on that call's row.

### Changed

- [kyo-sql] `SqlClient.reset` now drops the connection's prepared-statement cache, once the scrub has returned. A reset releases every server-side prepared statement, and the connection returns to the pool, so a cached entry naming one of them failed for the next borrower rather than for whoever called `reset`. A reset the server refused released nothing and leaves the cache alone, since forgetting the names there would strand the statements for the life of the connection. Affects the PostgreSQL, MySQL and Dolt backends; SQLite never had the failure.
- [kyo-sql] A PostgreSQL session that reports deallocating every prepared statement now drops the cache before the next statement binds. The command tag is what is read, not the SQL the caller was handed, so a `DEALLOCATE ALL` or `DISCARD ALL` sent through `executeRaw` is seen wherever it came from. Without this the next statement recovered through the retry below instead, at one dead Bind and one re-parse for every entry the cache still named, and inside a transaction block it could not recover at all.
- [kyo-sql] A PostgreSQL statement the server no longer holds is now parsed again and bound a second time, for the causes the driver cannot see: an external pooler's reset query, or DDL invalidating a cached plan. Only for `26000` from `FetchPreparedStatement` and `0A000` from `RevalidateCachedQuery`, only once, and only while the session is idle, since PostgreSQL aborts the whole block on a statement error. Inside a transaction block the original error is surfaced and the entry is dropped so the next statement heals. The pipeline path drops the entry and reports rather than retrying, because its batch has already run the later statements by the time the failure is read.
- [kyo-sql] A new `prepared_statements_reprepared` counter reports how often that recovery fired, alongside the existing pool counters.
- [kyo-sql] `SqlCodec.Writer` now states that encoding a value must be a pure, repeatable function of that value. Every shipped encoder already satisfies this; a user-supplied encoder over mutable state did not have to, and the retry above binds the same parameters twice.
- [kyo-sql] `Sql.Table`, `Sql.Insert`, `Sql.Update` and `Sql.Delete`: each carries a `schemaName: Maybe[String]` before its `tableName`. BREAKING for code that constructs or pattern-matches these AST nodes directly, which is what a custom `kyo.db.Idiom` does; the field has no default, because a default reaches the compile-time render as a synthetic accessor it cannot read and would make every statement unfoldable. Statements built through `Sql.from`, `Sql.insert`, `Sql.update` and `Sql.delete` are unaffected.
- [kyo-sql] Connection pool identity now includes the config's `SqlConfig.Extension` values, so two configs differing only in a backend setting do not share pooled connections. Idle retention per address can exceed `maxConnections` where it could not before; concurrency still cannot.
- [kyo-schema] `Schema.dictSchema`: non-String-key `Dict` now serializes each entry as a two-field `key`/`value` record (the same form `mapSchema` uses) instead of a bare two-element array. BREAKING: previously-serialized MsgPack bytes for a non-String-key `Dict` cannot be read by the new code. MsgPack was the only codec that decoded the old form; the other six failed to decode and Protobuf silently emitted corrupt bytes.
- [kyo-schema] `Schema.dictSchema` and `Schema.stringDictSchema`: a case class field holding an empty `Dict` now decodes on Protobuf instead of failing with `MissingFieldException`, matching the `Map` givens
- [kyo-core] `Fiber.init`: use `Scope` effect to guarantee termination of forked fiber
- [kyo-combinators] `.fork`: apply `Fiber.init` (formerly `.forkScoped`)
- [kyo-prelude] The `Parse` effect has been moved to a new `kyo-parse` module
- [kyo-core] `Log.live`: defaulting to `Unsafe.ConsoleLogger` for all platforms
- [kyo-core] `Path`, `System`, `Process`, `Command`, `CommandException`, `FileException`, and the `Stream` `writeTo` and `writeLinesTo` sinks have moved to a new `kyo-system` module. Add `"io.getkyo" %% "kyo-system"` to keep using them. No import or signature changes are needed, since the package is still `kyo`.
- [kyo-core] `Async.defaultConcurrency` now resolves through `StaticFlag`, which adds an environment-variable channel (`KYO_ASYNC_CONCURRENCY_DEFAULT`, checked after the `kyo.async.concurrency.default` system property) and changes the exception type thrown on a malformed value.
- [kyo-system] `Path.readStream(charset, bufferSize)`, `Path.readBytesStream(bufferSize)`, `Path.tail(pollDelay, bufferSize)`, and `Path.tailBytes(bufferSize)`: `bufferSize` is now a `ByteSize` rather than an `Int`. Pass `8.kib` where `8192` was passed. The value is clamped to the range an array can address, so `ByteSize.Zero` reads one byte at a time and anything above `Int.MaxValue` bytes reads through the largest buffer there is.
- [kyo-core] `Stream.fromInputStream(is, bufferSize)`: `bufferSize` is now a `ByteSize`, clamped the same way.
- [kyo-schema-json] `Json.Lines.DefaultMaxLineBytes` is now `Json.Lines.DefaultMaxLineSize`, a `ByteSize` of 16 MiB. The `maxLineBytes` parameter of `Json.Lines.Framer.init`, `Json.Lines.decodeAll`, `Json.Lines.decodeAllBytes`, `Json.Lines.decodeAllBytesResults`, and every `Jsonl` entry point is now `maxLineSize: ByteSize`. Pass `30.bytes` where `30` was passed. A ceiling above `Json.Lines.MaxLineSize` (`Int.MaxValue` bytes) is clamped to it, since a record is handed out as an array-backed `Span`.
- [kyo-prelude] `Stream.handle`: the handler's input is now typed as the stream's own pending computation instead of an inferred supertype, and its result is decomposed after inference. Handlers that only remove part of an effect keep the rest: `stream.handle(Abort.recover[Int](...))` on a `Stream[Int, Abort[Int] & Abort[Float]]` now infers `Stream[Int, Abort[Float]]` where it used to infer `Stream[Int, Abort[Any]]`. The first type parameter is the handler's result type rather than its input type, so an explicit type application such as `handle[A, V1, S1](...)` needs updating.
- [kyo-system] `Path.Unsafe.openWrite(append = true)`: now appends on Scala.js and Wasm. The Node handle wrote at an explicit position, which makes the call a positioned write, and POSIX leaves `O_APPEND` without effect there, so on macOS every write overwrote the file from its first byte. Writes now go at the file description's own cursor.
- [kyo-data] `ConcreteTag.accepts`: a primitive tag now asks the platform about its own type instead of classifying the value first. On Scala.js and Wasm every number is one runtime type, so the widest check answered for all of them and `ConcreteTag[Float]`, `ConcreteTag[Byte]` and `ConcreteTag[Short]` accepted nothing at all, which left `Abort[Float]`, `Abort[Byte]` and `Abort[Short]` unable to catch there. JVM and Native answers are unchanged. A JS number carries no width, so a widened numeric tag over-accepts on those platforms: `ConcreteTag[Double]` accepts `42`, and `ConcreteTag[Float]` accepts float-representable doubles.
- [kyo-system] A file write that reports no progress now fails with the new `FileWriteStalledException(path, remaining)` instead of being retried. Both write handles and both positioned raw channels retried a write that took no bytes, which re-offers the same bytes at the same offset forever and hung the calling thread with no diagnostic.
- [kyo-schema] `Schema.omitEmptyCollections` and `omit(_.f).whenEmpty`: an omitted empty `Map`, `Dict`, or `OrderedDict` field now decodes back to the empty value under either of that type's two givens, the object form or the array of `key`/`value` records. The injected value was chosen from the field's declared key type, which is not where a mapping's wire form comes from: a `Map[Int, V]` field failed to decode under its own default given, and a `String`-keyed field bound to `Schema.mapSchema`, `Schema.dictSchema`, or `Schema.orderedDictSchema` failed with `TypeMismatchException`.
- [kyo-schema] A schema transform (a rename, a drop, an omit policy, a discriminator, a representation) no longer rewrites a mapping field's wire form. A field whose given writes the array of `key`/`value` records keeps that form; it came out as an object whenever every key was a string, which the schema that wrote it could not read back.
- [kyo-sql] `SqlSchema` derived for a named tuple now carries the tuple's labels as the row's column names, so the row decodes by name as the equivalent case class does. `SqlMacros.columnNames` and the auto-key rule read them too. `Sql.from` on a named tuple now reports that the query DSL stages a row's columns from a case class's fields, rather than reporting a row with no fields.
- [kyo-slack] Every `SlackException` leaf is a final case class built from typed fields and compared by them, and none renders a cause into its message. `SlackTransportException(method, kind, host, port, timeout)` holds no kyo-http failure, since each names the request's url and a `response_url`'s path is its credential: `method` names the call (a Web API method, `apps.connections.open`, `socket-connect` or `response_url`), `kind` what failed (`Connect`, `Dns`, `Tls`, `ConnectTimeout`, `Timeout`, `Protocol`, `ConnectionClosed`, `WebSocketHandshake`, `PoolExhausted`, `PayloadTooLarge`, `NoResponseHead`), and kyo-net's failure behind a connection that could not be made is its `cause`. It is on every row, the four `response_url` ones included. BREAKING for code that built a leaf from a message string, or read the transport leaf's kyo-http cause: build it from its fields, and match `kind`.
- [kyo-slack] The client is a tracked requirement: every Web API and `response_url` verb carries `Env[Slack]` on its row, and `Slack.run`, `Slack.let` and `Slack.use` provide it, so a verb used where no client is provided does not compile. BREAKING for a helper whose declared row lacks it: add `& Env[Slack]`.
- [kyo-slack] The handler of `Slack.run` and `Slack.receive` is the polymorphic function `[A] => SlackEnvelope[A] => A < (Async & Abort[E] & Env[Slack] & S)`: `SlackEnvelope[A]` is indexed by the answer the case requires, a `SlackAck` for `EventsApi`, `Interactive`, `SlashCommand` and `Unknown`, and `Unit` for `Hello`, `Disconnect` and `UnknownFrame`. Acking a `Hello`, not acking an `EventsApi`, and a bare `case _` fallback do not compile. BREAKING: write the handler as `[A] => (env: SlackEnvelope[A]) => env match ...` with the fallback arms `case _: SlackEnvelope.Acknowledged => SlackAck.Ack` and `case _: SlackEnvelope.Plain => Kyo.unit`. `E` and `S` are inferred while the `run` expression has no expected type; bind it to a `val` before composing it, or pass `Slack.run[E, Any]`.
- [kyo-slack] `Slack.run` runs its own `Scope`, so its row no longer carries `Scope`, and it closes the client and every connection it opened when the loop ends.
- [kyo-slack] The module makes every request with its own kyo-http client under a complete `HttpClientConfig` (no redirects, no filter, no base url, default TLS), so no filter, base url or relaxed TLS of the caller's kyo-http client or configuration reaches a request that carries a token.
- [kyo-slack] `Slack.custom(method: SlackMethod, payload)` takes a validated `SlackMethod`, where it took a `String` placed into the url as given. BREAKING: wrap the name in `SlackMethod(...)`.
- [kyo-slack] `SlackToken.AppLevel` and `SlackToken.Bot` validate their text when built: the `xapp-` prefix, or `xoxb-` or the rotated `xoxe.xoxb-` for a bot token, then at most 255 characters in all, each printable ASCII other than space. BREAKING for a program that builds a token of another shape: it panics with `SlackInvalidTokenException` where the token is built.
- [kyo-slack] `Slack.Identity.url` is an `HttpUrl`, and an `auth.test` answer whose `url` is not absolute fails with `SlackDecodeException`; `SlackBlock.Image.imageUrl` is an `HttpUrl` and `SlackBlock.Element.Button.url` a `Maybe[HttpUrl]`, where each was a `String`. BREAKING: build the url with `HttpUrl`.
- [kyo-slack] `Reconnect.Off` delivers and acks the envelopes the connection already received behind a routine disconnect before the loop ends, where the teardown dropped them and any ack not yet sent.
- [kyo-slack] `SlackRateLimitException.retryAfter` is now `Maybe[Duration]`, BREAKING for code that read it as a `Duration`: `Absent` when Slack sent no `Retry-After` of ASCII digits, where a one-second delay was invented, and `Duration.Infinity` for a delay longer than a `Duration` holds. An `ok:false` body with no `error`, or a body with no `ok`, is now a `SlackDecodeException` rather than the code `unknown_error`, and a non-2xx answer with no Slack body, or with an `ok:true` body, is `SlackUnexpectedStatusException`.
- [kyo-slack] `SlackBlock.Raw(json)` parses its text when built and panics with `SlackInvalidRawBlockException` on text that is not an RFC 8259 JSON object, where it failed at send time with `SlackDecodeException`. `SlackConfig` panics with `SlackInvalidConfigException` on a zero or infinite `keepAliveInterval` or `ackDeadline`. Both constructors now take a `Frame`. BREAKING for a program that builds either value with such an input: it now panics where the value is built.
- [kyo-slack] `SlackToken.AppLevel` and `SlackToken.Bot` are classes rather than opaque `String` types, whose `toString` renders `SlackToken.AppLevel(<redacted>)` / `SlackToken.Bot(<redacted>)`, so a printed `SlackConfig` no longer shows either token; `value` still reads the secret. BREAKING for code that used a token as a `String`: call `.value`.
- [kyo-slack] `SlackAck`, `SlackEvent`, `SlackEnvelope` and `SlackInteraction` derive `CanEqual`, so values typed as the trait compare under strict equality.
- [kyo-slack] Every operation's row is its own failure trait instead of `Abort[SlackException]`: `Slack.chatPostMessage` is `Abort[SlackChatPostMessageFailure]`, `Slack.init` is `Abort[SlackInitFailure]`, and so on. Code that names `Abort[SlackException]` still compiles, since each trait extends it. `Slack.run` and `receive` take the handler's failure type as a new first type parameter `E`, inferred from the handler, and their rows are `Abort[SlackRunFailure | E]` and `Abort[SlackReceiveFailure | E]`. BREAKING for a call that applies `run` or `receive` type arguments explicitly.
- [kyo-slack] The code `rate_limited` is `SlackRateLimitException` on every operation, as `ratelimited` is, where some operations answered it as `SlackOtherApiException`. A code whose leaf belongs to a different operation is `SlackOtherApiException` on this one.
- [kyo-slack] `Slack.init` is `Scope`-managed: its row gains `Scope`, and the connection closes when the scope ends. BREAKING for a caller that kept the connection past the scope it was opened in: use `Slack.initUnscoped` and call `close`.
- [kyo-slack] A handler panic no longer ends `run` or `receive`. It is logged at error with the envelope's type and id, the envelope is left unacknowledged so Slack redelivers it, and the loop goes on; a typed handler failure still ends the loop. An envelope whose handler panicked is delivered again when Slack pushes its id again. BREAKING for a handler that relied on a panic to stop the bot: fail with a typed error instead.
- [kyo-slack] `SlackEnvelope.Unknown.payloadJson`, `SlackInteraction.Unknown.payloadJson` and `SlackEvent.Unknown.eventJson` are renamed `payload` and are a `SlackRawJson` instead of a `String`, whose `toString` renders the text's length, so a printed envelope no longer shows a payload's `response_url` or verification token. BREAKING for code that read the field by name or as a `String`: read `payload.value`. A skipped inbound frame is logged by its size or by the decoder's failure class, and a binary WebSocket frame by its byte count, never by their content.
- [kyo-slack] A payload missing a field its kind requires, or carrying a required id Slack sent empty, is delivered as that kind's `Unknown` with its raw JSON, instead of a typed case carrying empty strings. A slash command that fails to decode is a `SlackEnvelope.Unknown`, where it was a `SlackCommand` of empty strings. A `Hello` whose `debug_info` has no host has `debugHost = Absent`.
- [kyo-slack] `SlackEnvelope.Hello.debugInfo` is renamed `debugHost`: it holds only `debug_info.host`, not the whole debug info. BREAKING for code that named the field.
- [kyo-slack] `SlackEnvelope.Unknown` gains `meta: SlackEnvelope.Meta` and is acked; an unmodeled frame without an `envelope_id` is the new `SlackEnvelope.UnknownFrame(type, payload)`, a `Plain` case that takes no answer. BREAKING for a pattern that matched `Unknown` with two fields: add the third, and handle `UnknownFrame`.
- [kyo-slack] `SlackConfig.ackDeadline` defaults to `2500.millis`, where it was `3.seconds`, Slack's whole redelivery window, so an ack sent at the deadline arrived after it. A handler now has 500 ms less before the bare ack goes out.
- [kyo-slack] `SlackEnvelope.Meta.acceptsResponsePayload` is a `Maybe[Boolean]`, `Absent` when the frame does not say, where it defaulted to `false`. BREAKING for code that read it as a `Boolean`: match `Present(accepts)`.
- [kyo-slack] `SlackEvent.AppHomeOpened.tab` is a `Maybe[String]`, `Absent` when the person opened no tab, where it was `""`. BREAKING for code that read it as a `String`: match `Present(tab)`.
- [kyo-slack] `SlackInteraction.ViewSubmission.stateJson` is a `Maybe[SlackRawJson]`, `Absent` when the submission carried no state, where it was `"{}"`. It holds what the person typed, so a printed submission shows its length, not its content. BREAKING for code that read it as a `String`: match `Present(state)` and read `state.value`.
- [kyo-slack] `SlackEnvelope.DisconnectReason.Unspecified`: a disconnect whose frame names no reason, where it was `Unknown("")`, handled as a routine rotation. BREAKING for an exhaustive match on `DisconnectReason`: add the case.
- [kyo-slack] `Slack.authTest` fails with `SlackDecodeException(method, Payload)` when Slack's answer lacks `user_id`, `team_id`, `bot_id` or `url`, where it returned empty ids, and with `SlackDecodeException(method, Payload, ConstructorRejected)` at the field when Slack sent `user_id`, `team_id` or `bot_id` empty. BREAKING for code that tested an `Identity` field for `""`: handle the failure.
- [kyo-slack] `SlackEnvelope.EventsApi` gains `eventId: SlackId.EventId`, Slack's `event_id`, the id to deduplicate an event by; `SlackId.EventId` is new. An `events_api` frame without an `event_id` is delivered as `SlackEnvelope.Unknown`, acked. BREAKING for a positional pattern on `EventsApi`: add `, _` or bind the id.
- [kyo-slack] `SlackResponseUrl`: a `response_url`, held like a token. It renders as `SlackResponseUrl(<redacted>)`, is read through `value`, compares by value and has no `Schema`.
- [kyo-slack] `SlackCommand.responseUrl` is a `Maybe[SlackResponseUrl]`, `Absent` when Slack sent none, where it was a `String`, `""` when absent. BREAKING for code that read it as a `String`: use `responseUrl.map(_.value)`.
- [kyo-slack] `SlackInteraction.BlockActions` gains `messageTs: Maybe[SlackTs]`, the clicked message's timestamp, and `responseUrl: Maybe[SlackResponseUrl]`; `SlackInteraction.MessageAction` gains `responseUrl`. BREAKING for a positional pattern on either: add the fields, or bind the case and read its fields by name.
- [kyo-slack] No public inbound type has a `Schema`: `SlackEvent`, `SlackInteraction`, `SlackEnvelope` and each of their cases, `SlackInteraction.Action`, `SlackEnvelope.Meta`, `SlackEnvelope.DisconnectReason`, `SlackCommand` and `Slack.Identity`. Summoning one is a compile error naming the type. Their `Schema` read and wrote camelCase, not Slack's wire, and some hold a `SlackResponseUrl`; the module decodes Slack's frames itself. BREAKING for code that encoded or decoded them with kyo-schema.
- [kyo-slack] `SlackBlock.Element.Button.style` is a `Maybe[SlackBlock.Element.ButtonStyle]` (`Primary` or `Danger`), where it was a `Maybe[String]` any text went into; `SlackAck.ViewAction.Errors` is keyed by `SlackId.BlockId`, where it took `String` keys.
