# Size ceilings for the linkCheck programs, in bytes of linked output.
# <platform> <program> <bytes>
#
# `JS` and `Wasm` cap every output file. `JS-initial` caps the initial load, what a host fetches before any code runs:
# `main.mjs` and what it imports statically. The two differ once a link splits into chunks a host loads on demand; a
# WasmGC link is one module, so it has no separate initial ceiling.
#
# A program that links no network stack is one module, so its JS-initial line equals its JS line.
#
# Each ceiling is about 10% above the size measured when it was set, so ordinary growth passes and a step like
# the one in issue #1878 (the tz and locale data doubling a minimal program) fails. When a program grows for a
# reason worth its bytes, raise its line in the same change and say why in the commit.
#
# Measured at the change that removed the data artifacts and java.time from Instant:
#   JS    CoreMin 914,678   CoreLog 1,065,808   UiMin 544,385
#   Wasm  CoreMin 471,700   CoreLog   536,285   UiMin 271,315
#
# Measured at the change that moved every Node built-in off static imports (#1836 W3):
#   JS    CoreReadLine 1,799,710   SystemPath 2,191,164   NetEcho 3,304,836
#   Wasm  CoreReadLine   895,871   SystemPath 1,084,527   NetEcho 1,470,427
#
# Measured at the change that put a bare KyoApp and an HTTP-provider AI program in (#1836 W5):
#   JS    CoreApp 1,772,186
# CoreApp against CoreReadLine's 1,799,710 says what the 735 KB over CoreLog buys: the application runtime is
# 1.77 MB of it and reading a line is the remaining 27 KB.
#
# Measured at the change that took java.time out of the schema model, the UUID generator and the trace span (#1878):
#   JS    HttpGet 5,388,998   AiHttp 7,226,062   MachineStats 2,283,888
#   Wasm  CoreApp   876,393   HttpGet 2,228,208   AiHttp 3,022,652   MachineStats 1,107,591
# The Wasm row is the same programs through the WasmGC linker, and lands near 41% of the JS size on every one.
# Every program also lost weight here: CoreMin 914,678 to 879,915, CoreApp 1,772,186 to 1,759,327, NetEcho
# 3,304,836 to 3,284,716. The locale database is what left.
#
# Measured at the change that split the network stack by host (#1836, linking rule 2):
#   JS total    NetEcho 4,204,249   HttpGet 7,032,301   AiHttp 9,139,989
#   JS initial  NetEcho 2,448,495   HttpGet 2,956,975   AiHttp 6,001,117
# A page's initial load lost every Node backend: HttpGet 5,388,998 to 2,956,975, AiHttp 7,226,062 to 6,001,117. The
# totals grew by the names the linker gives references between modules, not by code: every such reference is
# spelled `$j_internal$002d<40 hex digits>.` and every module exports its members by full name. Removing those two
# from the output gives back NetEcho 3,284,013, HttpGet 5,418,151 and AiHttp 7,255,534: the single-module sizes
# above, plus the two classes that defer the load. Gzipped, the names cost NetEcho 537,102 against 475,703,
# HttpGet 868,466 against 769,498, AiHttp 1,090,002 against 982,979. A minifying bundler renames them.
#
# Measured when AiAuto was added, the provider-auto-detect path (#1836 W5):
#   JS 1,912,356   Wasm 937,884
# It resolves a config and prints, reaching no client, so it links no network stack: one module, and its JS-initial
# equals its JS. It is a fifth of AiHttp because it names no completion; what it is for is that it stays that way.
