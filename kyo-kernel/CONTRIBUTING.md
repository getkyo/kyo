# Contributing to kyo-kernel

Module-specific guidance for kyo-kernel, the effect system's kernel. Read the repository-root [CONTRIBUTING.md](../CONTRIBUTING.md) first: it carries the global conventions (naming, `using`-clause ordering and the `(using Frame)` type-parameter-separator pattern, `discard` for dropped results, the Unsafe Boundary tiers, the generic `Test[Any]` base-trait hierarchy, and the brief Effect Implementation Reference for `ArrowEffect`, `ContextEffect` and `Isolate`). This guide documents only what is true because of how kyo-kernel itself is built.

**The headline invariant: `A < S` is an untagged union whose three arms are told apart by runtime class alone, so a value is nested exactly once on the way in, carried opaquely in between, and unnested exactly once on the way out** (`Pending.scala`, the `<` opaque type alias). Every other rule in this module (the evaluator's dispatch, handler answers, continuation values, the `Loop` outcome protocol) is a consumer of that single fact. One extra or one missing nesting level makes the evaluator mistake a payload for a suspension, or hands a caller a box where it expected a value (`NestedTest`, "boxes a computation, so it travels as data" and "unwrapping strips exactly one level"). The section [Nest once, carry opaque, unnest once](#the-headline-invariant-nest-once-carry-opaque-unnest-once) is the deepest part of this guide because it is the part a change is most likely to break.

Topics the root guide already covers, followed here without amendment:

- `ArrowEffect[I, O]` as the extension point for function-like effects parameterized by input and output type constructors: root CONTRIBUTING.md, Effect Implementation Reference > Anatomy of an Effect.
- The three-phase `capture` / `isolate` / `restore` protocol of `Isolate`: root CONTRIBUTING.md, Effect Implementation Reference > Isolate Protocol for Fiber-Crossing Operations.
- Exposing multiple write-back policies as `update` / `merge` / `discard` in an `object isolate` namespace: root CONTRIBUTING.md, same section.
- The leading type-parameter list before `using Frame` for entry points that need one explicitly-named type argument: root CONTRIBUTING.md, API Design > Method Signatures.
- `discard(...)` rather than `val _ =` for an intentionally-dropped result: root CONTRIBUTING.md, Code Conventions > Scala Conventions.

A contributor arriving with a concrete task rather than reading start to finish should jump straight to [Checklist: adding a new X to kyo-kernel](#checklist-adding-a-new-x-to-kyo-kernel), which routes to the matching recipe under [Extension recipes](#extension-recipes): Recipe: add a new ArrowEffect, Recipe: choose and write the handler, Recipe: tag choice, and when to erase it, Recipe: add a new ContextEffect, Recipe: add an Isolate, Recipe: mask an effect between two points, and Recipe: add to the kernel's own surface.

| Re-exports | `kyo/kernel.scala` aliases `<` and `Loop` into package `kyo` and exports `Arrow`, `Isolate` and `Region`, plus the `Id`/`Const` type constructors every effect definition uses | `kernel.scala` |
| Node representation (`kyo.kernel.internal`) | `Kyo` is the supertype of two families: `Pending`, the sealed node ADT whose shapes are `Defer`, `Suspend` (`SuspendArrow`, `SuspendContext`), `Handle` (`HandleArrow`, `HandleContext`), `Snapshot` and `Park`; and `Arrow`, the reified continuation | `KyoInternal.scala`, the `Kyo` trait; `PendingInternal.scala`, `Pending` and its subclasses |

Two structural facts shape everything else in the module:

- `Effect`'s constructor is `private[kernel]`, so the hierarchy fans out to exactly two kinds and no downstream module can add a third: `ArrowEffect` for suspended computations with input/output transformations, `ContextEffect` for suspended computations requiring contextual values (`Effect`, the `private[kernel]` constructor).
- `Arrow[-A, +B, -S]` is the module's function-like link, deliberately not a `Function1`: `Function1` is `@specialized` on both parameters, so every class mixing it in emits the whole `apply$mcXY$sp` forwarder grid, with no genuine call site anywhere in the module. Handlers take an `Arrow` directly, which also spares the eval an eta-expansion per suspension (`Arrow`, the `sealed trait` declaration).

Regions are not arrows. A region is a `Handle` node the evaluator turns into a `Stack` entry, so nothing can fold one into a continuation and defeat the scans that find it (`Pending.Handle`, `Stack.find`). What the `Arrow` hierarchy itself distinguishes is `Chain`, a composition the evaluator unfolds into head and tail, from `Transform`, an atom that is its own head; and inside `Transform`, `Ensure` is the one arrow that applies without taking the safepoint budget, so no preemption lands between a value arriving and the function that records what that value owes (`Arrow.Chain`, `Arrow.Transform`, `Arrow.Ensure`). [Evaluation laws](#evaluation-laws) explains what those distinctions buy.

### One operation, end to end

1. **Suspension.** An `ArrowEffect` operation allocates one `SuspendArrow` node carrying frame, tag, input and the identity continuation. Nothing runs (`ArrowEffect.suspend`).
2. **Region install.** `handleCont` / `handleContRepeated` / `handleLoop` / `handleLoopState` build a `HandleArrow` node holding the unforced body, the handler, the handler's initial state and the region's own continuation; the eval pushes handler, state and continuation as one stack entry, then descends into the body (`Pending.HandleArrow`, and the `Pending.HandleArrow` arm of `Eval`'s loop).
3. **Dispatch.** The eval scans down the stack for the innermost handler whose tag matches and errors out if none exists; the suspension's own continuation is chained onto the ones in flight and handed to that handler (`Stack.find`, `Eval.unhandled`).
4. **Answering.** The handler subclass decides the protocol. The fast path fires only when the matched handler is the innermost entry on the stack; otherwise the entries above it are folded into the crossing continuation by `Eval.dumped` before the clause is called (`Eval.dumped`, `Pending.Suspend.crossing`).
5. **Delivery.** When the current value is settled and no continuation is in flight, the eval reads the innermost stack entry and ends that region: a `ContextHandler` unbinds its value, any other handler runs `done` over the unnested value. With a continuation still in flight, the eval unfolds it and applies it (`Eval`'s settled arm, `Handler.ArrowHandler.done`).
6. **Exit.** Both ways out drain the releases the evaluation left unclaimed: the clean path through `drainDiscarded`, the failing path through the unwind, which drains before it rethrows. Restoring the caller's safepoint state and returning the stack to the pool sit in a `finally` around both, so neither is skipped by an escaping exception (`Eval.drainDiscarded`, `Eval.recovered`, `Safepoint.restore`, `Stack.release`).

`ArrowEffect.Mask` shows how far the region API reaches on its own: `Mask.run` is a single `handleCont` whose clause re-applies the continuation. What it does need from the kernel is the masking region itself, since shadowing a tag has to be visible to a context read as well as to the stack scan, so the entry side is `handleMasking` over a `MaskingHandler` that hands the clause the operation rather than its input (`ArrowEffect.Mask`, `ArrowEffect.handleMasking`, `Handler.MaskingHandler`). `Kyo.scala` is the other end of the same point: over 2700 lines of `foreach` / `filter` / `foldLeft` / `zip` / `collect` built purely on the `map` bind and `Loop`, importing nothing from `kyo.kernel.internal` and touching no node or `Eval` API (`Kyo.scala`, its import list).

## The headline invariant: nest once, carry opaque, unnest once

### What the union is, and what it buys

`opaque type <[+A, -S] = A | Pending[A, S] | Nested[A]` (`Pending.scala`, the `<` alias). A settled value, a suspended node, and a `Nested` box for a value that is itself union-shaped are all the same static type, and they are told apart only by runtime class. Every public signature in every downstream module is written in this type.

`Nested` exists for one job: to disambiguate the union's first two arms. `nest` and `unnest` are the two operations that enter and leave the box (`Nested.nest`, `Nested.unnest`). Nothing else in the module is allowed to invent a fourth arm or a second boxing scheme.

### The three mechanisms, each tied to one operation kind

**Nest, at the lift boundary.** Entering the union boxes only a value that would itself read as a computation; everything else crosses unwrapped:

```scala
def nest[A, S](v: A): A < S =
    v match
        case v: (Pending[?, ?] | Nested[?]) => Nested(v).asInstanceOf[A < S]
        case _                              => v.asInstanceOf[A < S]
```

(`Nested.nest`). The public entry to that is the implicit lift, which resolves the primitive and `String` cases at compile time to a pure cast and only otherwise pays the runtime nest test (`Implicits.lift`). Nesting is one level per lift and is applied again to an already-boxed value rather than being idempotent (`NestedTest`, "boxes an already-boxed value again, one level per lift").

**Carry opaque, in the evaluator.** The evaluator is one flat `@tailrec` loop dispatching on the node's class, and its type arguments are erased at every recursive call, so everything the kernel returns into it has to be union-shaped whatever its static type reads as (`Eval.apply`, the `loop` definition). A node's payload is a value already in hand, never a body to run: a deferred computation defers because its arrows have not been applied, not because reading the node runs anything, which is what lets an inspection walk through a deferral to the operation behind it without evaluating a step (`Pending.Defer`, its `value` / `contA` / `contB` members).

**Unnest, at every strict delivery.** `Nested.unnest` strips exactly one level and is only legal at a site that has already excluded the pending arm (`Nested.unnest`), pinned by test so a consumer that unnests twice or not at all is caught (`NestedTest`, "unwrapping strips exactly one level"). Every strict path in the kernel calls `unnest` before handing a payload to user code.

`Nested.unnest` takes `Any`, not `A < S`: typed at the union, the implicit lift would be in scope at every call site, and lifting a value that is already union-represented corrupts it (`Nested.unnest`, its signature).

### The discrimination shape every consumer repeats

Every consumer of the union discriminates in the same order and the same shape: test the `Pending` arm first and reify through `Effect.defer`, otherwise take the safepoint budget and, if it is granted, unnest exactly once and apply strictly:

```scala
v match
    case v: Pending[A, S2] @unchecked =>
        Effect.defer(v, this, cont)
    case _ =>
        val slot = Safepoint.get()
        if !Safepoint.enter(slot) then
            Effect.defer(v, this, cont)
        else
            val out = cont.head(apply(Nested.unnest(v)), cont.tail)
            Safepoint.exit(slot)
            out
```

(`Arrow.apply`). The same three-arm discrimination is written out at every site that mints a standalone arrow, in the same order (`Arrow.recursive`, `Arrow.Ensure.apply`, and `flatten` in `Pending.scala`). The bind combinators fuse the two tests into one boolean and build the `DeferWith` node inline rather than calling `Effect.defer`, but they discriminate on the same arms in the same order (`Pending.scala`, the `run` local in `map`, `flatMap`, `andThen` and `unit`). `Render` for the pending type shows the canonical arm order for inspection: pending node, box, raw value (`Pending.scala`, the `Render` given).

`Effect.defer(v, cont)` is the reification of an application that could not run strictly, and it is defined to be observationally exactly `cont(v)` (`Effect.defer`). The budget arm is not an optimization: application on a settled value runs strictly until the safepoint budget drains, at which point it reifies instead of recursing (`Safepoint.enter`, `Safepoint.enterPark`), and construction past the budget completing rather than overflowing is pinned as a behavioral guarantee (`PendingTest`, "construction past the safepoint budget rescues instead of overflowing").

### Where the union rejects you, and where it must not be bypassed

- **A doubly-pending type is a compile error, not a silent lift.** `CanLift` rejects `A < S1 < S2` with a teaching message; the fix is `.flatten` or splitting the expression, never a cast (`CanLift`, its `@implicitNotFound` message). The guard is real, so an ordinary `map` result cannot be silently re-nested, and the rejection is asserted as a compile failure (`CanLiftTest`, "not compile for known Kyo types").
- **Kernel-internal code must not summon the lift.** It puts a raw value into the union directly, by cast or by ascription: a raw value is already the union's first arm and `Unit` admits no `Nested` subtype, so there is nothing to nest, and under `-Xcheck-macros` the inline body sees `<` through a proxy the compiler does not substitute into the union, leaving the lift nothing to conform to (`Effect.unitValue`, and the cast comments in `Pending.scala`'s `map` and `unit`).
- **A cast that stands in for the lift must say why the value cannot be `Nested`.** That statement is the only thing making the cast equivalent to the lift. `Loop.continue` may cast because the `Continue` it has just allocated is by construction neither a node nor a box (`Loop.continue`).
- **Substituting a cast for the lift where the payload can itself be a computation is a defect.** Only the nest keeps the evaluator from mistaking data for a suspension, which is why `Loop.done` cannot make `continue`'s argument about an arbitrary answer: it calls `Nested.nest`, and boxes a `Continue`-shaped answer in `Done` so the loop cannot read a final value as a request to continue (`Loop.done`, `Loop.Done`). Both halves are pinned (`LoopTest`, "outcome payloads held as data" and "outcome payloads that are outcomes").
- **The one deliberate re-nesting point in the public surface is `Isolate.nest`**, which calls `Nested.nest` with its type arguments stated so the runtime analysis nests the payload exactly once. The implicit lift cannot be summoned there: its guard rejects the syntactically pending `A < Restore` (`Isolate.nest`).

### The same discipline, one layer up

- `Loop.Outcome` is the union discipline applied to clause results: `opaque type Outcome[A, +O] = O | Continue[A]`, a bare final value or a `Continue`, told apart by class (`Loop.Outcome`). It inherits the collision the union has, so `Loop.done` needs its own box, `Done`, for a final value that is itself a `Continue` (`Loop.Done`).
- A handler clause's answer crosses back to the evaluator as one `Outcome` value that is itself union-shaped, so three cases arrive on the same wire and only the dispatch tells them apart: a `Pending` node means the clause suspended before answering, a `Continue` means resume (carrying the next state, in `Continue2`, for the stateful form), anything else is the region's final value (`Handler.LoopHandler.answers`, `Handler.LoopHandler.clauseDispatch`).

### Config knobs on the strict path

| Knob | Default | Constraint | What it governs | Anchor |
|------|---------|-----------|-----------------|--------|
| `Safepoint.period` | `maxStackDepth`, 512 | clamped to `[1, 0x7fff]`, `StaticFlag[Int]`, identical on both platform variants | strict applications fused per slot before the eval takes over | `Safepoint.period` on both platform variants; `maxStackDepth` in `kernel/internal/package.scala` |
| `Safepoint.slotCount` | 65536 | must be a power of two; jvm-native only, since JS and Wasm run every evaluation on one thread | sizes the slot table; a thread that cannot claim a slot degrades to the shared overflow slot | `Safepoint.slotCount`, `Safepoint.resolve`'s `claim` returning `Overflowed` |

Those two are the only knobs. In particular the handler's fused answer walk has no bound of its own: it keeps consuming same-tag suspensions until the answer is pending, the next tag differs, the clause throws, or the armed preemption check fires, so what ends it is the stop channel rather than a count (`Handler.answersLoop`, `Handler.answersLoopState`).

### What a new method over the union must do

1. Discriminate in the canonical order: `case v: Pending[A, S] @unchecked => Effect.defer(...)` first, spelled identically to every other strict/deferring fork in the module (`Arrow.apply`, `Arrow.Ensure.apply`, `Handler.LoopHandler.clauseDispatch`).
2. Read the settled arm through `Nested.unnest`, never with a bare cast at the use site (`Nested.unnest`); it sits in the same position in the bind expansion and in the region combinators (`Pending.scala`, the `run` local in `map`; `Pending.handle`, its settled arm).
3. Take the budget before applying strictly, and fall into `Effect.defer` when it is denied (`Arrow.apply`, `Effect.deferInline`).
4. Bind an inline receiver into a local exactly once: the extension parameter is inline, so every occurrence re-expands the receiver expression, and two occurrences would build the computation twice and run the function twice on the settled path. `map`, `flatMap`, `andThen` and `unit` each pass it to a local non-inline `run` in a single position, and every `handle` arity binds the stage below it to a local `def`, which keeps it by-name, before the next function sees it (`Pending.scala`, the `run` locals and the `handle` overloads).
5. Return a value of the union, never a bare payload the loop would have to guess at. `Any < Nothing` is the shape every arm hands back, and it is the same type the lift's guard tests against to recognize a pending value (`Eval.apply`, the `loop` definition; `CanLiftMacro.liftImpl`).

## Evaluation laws

These are the rules a new effect, handler or combinator has to respect. They follow from the representation above.

**Unhandled is a bug, not a state.** An operation reaching the evaluator with no handler anywhere fails: the row rules it out for both entry points, since a slice takes `A < Any` as well (the `eval` extension in `Pending.scala`, `Eval.partial`), and the throw `bug` raises is caught so the effect trace can attach to it before the same exception is re-raised (`Eval.unhandled`). What a caller sees is "unhandled suspension" (`EvalTest`, "an unhandled operation is a bug").

**A nested eval sees none of the enclosing regions.** An `Eval` called from inside a running computation takes its own stack from the thread's pool, the enclosing one being checked out for as long as it runs (`Stack.borrow`), so any effect still in the inner row fails as "unhandled suspension" at runtime (`EvalTest`, "a nested eval shares the thread's stack and sees none of the outer regions").

**Handler lookup and binding lookup are the same relation.** A suspension is answered by the innermost enclosing handler whose tag is a subtype of the operation's, the scan stopping at the first match (`Stack.find`), and a context read resolves the same way, walking outward to the innermost binding whose tag is a subtype of the read's (`Context.get`). The direction is what lets a region handling a wider row answer a narrower operation: the effect parameter is contravariant, so `Abort[Any]` is a subtype of `Abort[E]` and the region that catches everything answers a fail of `E`. [Tag choice](#recipe-tag-choice-and-when-to-erase-it) is where that becomes a design decision.

**Regions must stay findable.** A region exists by being an entry on the evaluator's stack: a handler, its state, and the continuation to resume when its extent ends (`Stack.push`). Nothing else finds one, so an arrow must never carry one: `Stack.find` is the handler scan, `Context.get` the binding scan, and the per-entry lanes of owed snapshots are what a drain walks (`Stack.owe`, `Stack.takeOwed`). The arrow family is kept to what cannot hide a region: `Id`, `Step` (with `Ensure` as the one step the abandonment walk below may run), and `Chain`, the deliberately unnormalized shape a computation accumulates in while it is being built, so accumulating stays O(1) per combinator (`Arrow`). `Stack.dump` is where the split earns its keep: the entries between a handler and the suspension it is answering come off the stack as one immutable snapshot the continuation carries, and the same snapshot is recorded in the answering handler's own owed lane, so whichever of the two ends first can still find it (`Stack.dump`). Outstanding releases live in that lane rather than as entries for exactly the same reason: an entry the eval pops is gone, while what it owes has to outlive the pop.

**Continuations are complete values.** `ArrowEffect` supports multi-shot continuations: a clause may invoke the continuation many times or not at all (`ArrowEffect`). Every shot replays the trailing maps folded into it, once per shot, at any depth (`EvalTest`, "a continuation applied twice replays trailing maps twice at any depth"), and a continuation stays valid after the eval that produced it has completed, each shot resuming from capture-time state (`EvalTest`, "stays valid after its eval completes, replaying the trailing maps once per shot", "each shot of a multi-shot capture resumes from capture-time state"). A clause's continuation is confined to that clause by `Region.NoEscape` in its row, so keeping one past its region takes the explicit `Region.leak`, which is what the kernel's own tests use to reach this behavior.

**A settled body installs no region.** The combinator short-circuits to the `done` clause applied strictly to the unnested value, so a clause with observable behavior never runs (the settled arm of every `ArrowEffect.handleCont` and `handleLoop` variant, and `Pending.handle`), pinned by test (`EvalTest`, "a settled input applies done strictly").

**Bindings layer, they do not replace.** A region derives its value from what is bound outside it when the entry is installed, so nested scopes of one effect layer rather than overwrite (`ContextEffect.handle`'s `derive`, applied in the eval's `HandleContext` arm), and the region's exit reverts the binding to the enclosing one (`EvalTest`, "a context region's exit reverts its own binding to the enclosing one"). `Context.Bound` is one node kind for both a value binding and the marker a masking region leaves behind, which is what lets one mask cover both kinds of effect (`Context.bind`, `Context.mask`). A park carries its own region entries and reinstalls them on resumption, so a parked computation resumed under a different enclosing binding still reads the one it was parked under, not the one now in force (`Eval.installed`; `EvalTest`, "a resumed region restores its parked binding"). `Pending.Snapshot` is the one node kind handed the whole stack rather than one entry: a crossing reads the contextual regions out through it on the way in and writes each joined state back into the scope that owns it on the way out, in a single visit (`Isolate.Contextual.capture`, `Isolate.Contextual.join`).

**A release runs exactly once.** The run is CAS-guarded and the flag is set before the release runs, so a throwing release still counts as run (`Bracket.Cell.Live`). It is an `AtomicBoolean` rather than a plain `var` because a captured continuation can be resumed on one thread while the eval that created it drains on another, so the two paths genuinely race. `Bracket.Cell` fills three roles at once: the state the region's `ContextHandler` holds, that exactly-once guard, and the record of whether the extent ever ran to an end, which is what a later discharge reads to tell a clean ending from a discarded one (`Bracket.Cell.Live.discharge`). What a release is told is how the extent ended, `(A, Maybe[Throwable])`: `Absent` for a clean end, otherwise the failure that unwound it or the discard signal. It is never told what the use produced, because an extent a handler replays ends more than once, with more than one value (`Bracket.apply`). Re-entering a region whose release already ran is refused at the entry with `kyo.Closed`, before the code inside can read what is gone (`Bracket`'s `reenter`; `BracketTest`, "a leaked capture resumed after its region completed is refused as closed"). A region that ends drains what it still owes, because a clause that completed without resuming its continuation orphaned those extents, and the signal it drains them with is "remainder discarded" (`Eval.drainDiscarded`). Two flags on `Handler` say who that owner is. `repeated` declares that the clause resumes its continuation more than once, so the regions dumped into it are held: an ending only records its outcome, and the debt discharges once, where the declaring handler ends (`Handler.repeated`, `Eval.held`, set by `ArrowEffect.handleContRepeated`). `escaping` declares that the clause hands the continuation out as a value, so the debt moves to the scope below rather than being discarded at the region's exit, to be settled when the remainder resumes and drained at that scope's exit if it never does (`Handler.escaping`, `Eval.arrowExit`, set by `ArrowEffect.handleFirst`). `ArrowEffect.handleFirstRepeated` sets both, for a peel whose remainder is applied more than once.

**Failure unwinds on one walk.** A failure unwinds the entry stack from the top, offering each region's recovery clause the failure and running every release it passes on the same walk, so a bracket opened inside a guarded scope releases before the recovery runs (`Eval.recovered`; `BracketTest`, "a bracket under a recovering handler releases with the failure, before the recovery"). A clause's own failure is offered to its own region's recovery, and escapes the region when there is none or it declines (`ArrowEffectTest`, "recovers a throw in the handler", "a clause throw escapes the region on the fast and general cont paths"); the regions that sat between that handler and the suspension were dumped into the continuation before the clause ran, so they release on the unwind without their recoveries being consulted (`Eval.dumped`, `Eval.drainOwed`; `ArrowEffectTest`, "a clause throw releases the interior brackets it escapes"). A release that throws is suppressed onto the failure rather than replacing it (`Eval.released`). Recovery re-enters the eval through a `@tailrec` outer function rather than a `try` inside `loop` or a recursive call, because a tail call may not sit inside a `try` and a recursive retry would cost a JVM frame per recovery (`Eval.guarded`; `EvalTest`, "regions that fail and recover in sequence cost no stack").

**A park is a whole eval state snapshotted as a value.** `Pending.Park` holds the remaining computation, the region entries, and what those entries owe; the entries are an immutable `Span` packing handler, state, continuation and owed lane per region, so a parked computation is resumable more than once and on any thread (`Pending.Park`, `Stack.Snapshot`). Resuming reinstalls the entries and re-enters each region, which is where a bracket already released refuses (`Eval.installed`). A park carries its outstanding releases rather than running them, which leaves the holder the choice; the holder that gives up calls `Eval.release` (`IOTask`). The stop is honored on a clause's answer rather than before it, because a clause that re-raises its operation would otherwise dispatch straight back with no deferral to park at (`Eval.loop`; `EvalTest`, "a clause that requests a stop and re-raises its operation parks in front of the re-raise"). A park landing in front of an `Ensure` that has not been applied is allowed, and the abandonment walk is what pays for it. The plain `Eval.release` walks a computation and runs nothing, so a caller releasing a continuation it has just refused does not run the very thing the refusal exists to stop; the budgeted overload, the one a fiber abandonment uses, spends a unit of budget per step to reach a release waiting one step further in. Either way the walk carries the continuation down to its leftmost step and offers an already-settled value to an `Ensure` waiting on it, then walks what applying that `Ensure` yields, at no budget: one that installs a region to own the release, as `Bracket` does, has only just created the debt, where one that registers elsewhere, as `Scope.acquireRelease` does through `ensureMap`, has discharged it by being applied (`Eval.release`, and its `leftmost` and `ensuring`; `EvalTest`, "a release waiting on a value that already arrived is found on abandonment", "a release the abandoned Ensure installs rather than registers is still run"). The isolate path reuses the same node: a crossing builds a `Park` around the body carrying the forked region entries, so one representation serves both crossing and parking (`Isolate.Contextual.isolate`).

**The generated answer protocol.** The answer templates live in `Handler` because the protocol is the eval's, but each region call site expands its own copy with the clause statically bound, so the whole walk is one compiled method per site (`Handler.answersLoop`, `Handler.answersLoopState`); the wiring side overrides the generic `answers` body with the template instantiated at that site (`ArrowEffect.handleLoop`, `ArrowEffect.handleLoopState`). State and branch cross back as a `Loop.Outcome`, an opaque union of the final value with a `Continue`, so an answer that ends the region is the value itself and costs no allocation, and only a continuation buys an object (`Loop.Outcome`, `Loop.Outcome2`). The template fuses consecutive answers of the same tag in place rather than returning to the eval, matching both a bare suspension and a deferral holding one, and hands control back the moment the next node is anything else or the slice is stopped (`Handler.answersLoop`).

**Two cost contracts that read as style but are not.** The order of the arms in the eval's match is a performance contract: the rare nodes, `Park` and `Snapshot`, come last so common computations never pay a failed type test for them (`Eval.loop`). And `Eval.apply` is deliberately neither `inline` nor `@static`: it is an interpreter large enough that HotSpot refuses to inline it anywhere, so an inline definition bought nothing at runtime and emitted a private copy of the whole thing per call site, while Scala.js cannot emit a static method containing a lambda (`Eval.apply`).

**The two seams cost nothing when unused.** `Debugger` is behind a compile-time flag: `Debugger.enabled` reads `CompileTimeFlag.boolean("kyo.kernel.internal.Debugger.enabled", false)` and every hook is an `inline if enabled`, so a build with the flag off compiles the calls away and never loads the real subclasses, which live in the debug tooling module (`Debugger.enabled`, `ConsoleDebugger`); the gate leaves no inline accessor behind either (`DebuggerBytecodeTest`). `EffectTrace` records nothing while a computation runs: the frames are reconstructed at the boundary an exception crosses, from the failing node and the eval stack already in hand (`EffectTrace.reconstruct`). `maxTraceFrames`, 64, is one total cap across every boundary an exception crosses, innermost first, since each boundary builds with only what the carrier has not already spent (`maxTraceFrames` in `kyo/kernel/internal/package.scala`). Keeping kernel internals out of a user-visible stack trace is a prefix test rather than a list to maintain: every physical frame under `kyo.` is dropped from what gets spliced in (`EffectTrace.isPlumbing`).

## Conventions

### Cast discipline

- Read the settled arm through `Nested.unnest`, not a bare cast, at every strict arm across the module (`Nested.unnest`, and its callers `Pending.map`, `ArrowEffect.suspendWith`, `Arrow.apply`).
- A cast an erased slot or an existential type forces is prefixed "Erasure-forced:" and names what was erased, stated at the walk that performs it rather than repeated at every cast inside that walk (`Eval.release`, on the operation's input type and on the types joining a chain's links).
- A cast standing in for the implicit lift states why the value holds by construction and what the compiler cannot see there, and the sites that repeat it point back at that one statement rather than restating it (`Pending.map`'s cast on its receiver, then `Pending.flatMap`, `Pending.andThen` and `Pending.unit` carrying "Cast per `map`'s note above"; `Implicits.lift`, on why its type arguments are stated rather than inferred).
- A cast that asserts a representation rather than a type says which liberty it takes and what makes it hold (`Region.discharge` and `Region.leak`, both on the row being phantom).
- Where a new hook would otherwise force the evaluator to cast, the hook takes `Any` and the narrowing moves to the implementor (`Debugger.onAlloc` and `Debugger.onLoop`, narrowed by pattern match in `ConsoleDebugger`).

### Inline usage

The root guide's default is that handling paths are not `inline`. This module inverts that for the region and handling combinators, because the clause has to be statically bound into the per-call-site answering loop, which is the mechanism the design exists for (`Handler.answersLoop`, `Handler.answersLoopState`; contrast root CONTRIBUTING.md, Optimization > Inline Guidelines). The rest of the inline rules here:

- The evaluator itself is never `inline`: its entry point and every handler entry it calls at runtime are plain methods (`Eval.apply`, `Handler.ContHandler.answering`, `Handler.LoopHandler.answers`).
- The cold arm an inline expansion falls into is a plain public method, so the site pays a call rather than a class (`Effect.defer`, reached from the cold arms of `Effect.deferInline` and `Arrow.apply`).
- Each region combinator's `answers` override hands its clause to the matching `Handler` template as a polymorphic function literal, which is what binds the clause statically at that site (`ArrowEffect.handleLoop`, `ArrowEffect.handleLoopState`).
- Every inline def whose expansion allocates an anonymous class carries `@nowarn("msg=anonymous")`, on the inner non-inline def when the allocation sits there; it is the only `@nowarn` message used anywhere in the module's main sources (`ArrowEffect.suspend`, `Arrow.apply`, `Pending.map`'s `run`).
- A `private[kyo]` or `private[kernel]` object an inline body names carries `@publicInBinary`, so the accessor the expansion emits resolves at an expansion site outside package `kyo` (`Nested`, `Handler`, `Eval`, and `Pending.fromKyo`).
- An inline receiver or inline parameter read more than once is bound to a local exactly once (`ArrowEffect.handleCont`'s `val v0 = v`, `ArrowEffect.handleLoopState`'s `val state0 = state`).
- A clause or by-name parameter used inside the anonymous class an expansion builds is first wrapped in a local `on<Clause>` def, because the class member of the same name would shadow the parameter (`ArrowEffect.handleLoop`'s `onDone`, `ArrowEffect.handleCont`'s `onRecover`).
- The `Frame` given is named `_frame` whenever the expansion's anonymous class defines a `frame` member, and plain `frame` when it does not (`ContextEffect.suspend` and every other combinator that builds a node; `Pending.eval`, which builds none).
- An inline template body loops with a `running` flag rather than an early return, because an inline body cannot `return` (`Handler.answersLoop`, `Handler.answersLoopState`).
- The region combinators take the body's row and a free row as a pair (`S`, `S2`), stated on `ArrowEffect`'s own scaladoc and repeated on the entry of each handling family (`ArrowEffect.handleCont`, `ArrowEffect.handleLoop`, `ArrowEffect.handleLoopState`).

An inline body that selects a `private[kyo]` name qualified, or names a `private[kyo]` top-level object without `@publicInBinary`, breaks only outside package `kyo`, which no in-package test can see. That is why every new public inline entry point goes into the outside-`kyo` suite (`outsidekyo.KernelTest`).

### Visibility, `@static`, and the inline-expansion boundary

What an inline body names has to be reachable at the expansion site, at both the object and the member level. Two shapes satisfy that, and the module uses only those two: a public object whose members are `private[kyo]` (`Safepoint`), and a `private[kyo]` or `private[kernel]` object carrying `@publicInBinary` (`Nested`, `Handler`, `Eval`). The whole module's visibility layout follows from that one constraint:

- Reach forced by an inline expansion is paid back by withholding operations: the exposed types are opaque, and the class behind a public object stays private (`Safepoint.Slot` and `Safepoint.State`, opaque; `class Safepoint`, private behind the public `object Safepoint`).
- An opaque type gets only the bound a caller genuinely needs, declared identically on both platform variants (`Safepoint.Slot`, with a lower bound and no upper bound, on the jvm-native and js-wasm `Safepoint` alike).
- Where a class is public and holds mutable state, the state is narrowed rather than the class being opened (`EffectTrace`'s `elements`, `dropped`, `physical`, `seen` and `seenEpoch`, all `private[kyo] var` on a public class).
- Visibility narrows to the smallest qualifier that compiles, including type-scoped qualifiers such as `private[Arrow]` and `private[Safepoint]`, not just `private[kyo]` (`Arrow.Id`'s constructor, `Safepoint.State`'s extension members). This refines the root guide's Visibility Tiers table, which lists only public, `private[kyo]` and `private`.
- Cross-platform members keep matching visibility even where a platform would allow narrower, because shared inline expansions name them (`Safepoint.drain`, `Safepoint.arm` and `Safepoint.stopped`, `private[kyo]` on both variants).

`@static` is confined to the jvm-native `Safepoint`: its slot arrays and every accessor over them carry it, and no other object in the module uses it at all. The js-wasm mirror declares the same members without it. What makes an internal object reachable from an inline expansion is `@publicInBinary`, not `@static`: `Nested`, `Handler` and `Eval` carry that annotation and declare plain module methods. An object carrying `@static` members is paired with an otherwise-empty companion class, kept `private[kyo]` under the public object (`class Safepoint` under `object Safepoint`).

### Comments in internal files

- A comment on an internal type or member says what the thing is and why it has that shape, not what its methods do (`Kyo`, `Handler.repeated`, `Handler.escaping`, `Handler.bound`, `Handler.MaskingHandler`, `Bracket.Cell`).
- The justification idiom is "X rather than Y: reason", which names the rejected alternative in the same sentence as the choice (`Bracket.Cell`, on two shapes rather than one with a flag; `Pending.fromKyo`, on public in binary rather than inline; `EffectTrace.Builder.frame`, on skipping a null frame rather than letting it fail).
- A performance claim names the test that pins it rather than a number that will rot (`Pending.fromKyo`, pointing at `ArrowEffectBytecodeTest`).
- A shape that was tried and failed is recorded with the failure it produced, naming the test or the compiler mode that caught it (`Implicits`, naming the `PendingTest` case that forced the lift out of the `<` companion; `Pending.map`'s cast note and `Implicits.lift`'s, both naming `-Xcheck-macros`).
- Where the arm a value lands in is load-bearing, the arm says why it holds rather than leaving a reader to reconstruct the union (`Pending.unit`, on `Unit` being the union's first arm).
- Where a reader would otherwise clean something up, the comment says why it stays (`Stack.pop`, on nulling the popped slots and on deliberately not clearing `owed`).

### Naming

- The evaluator's erased types are abstract type members on `Eval` itself: an `X` family for the operation in flight (`IX`, `OX`, `EX`, `VX`, `CX`, `AX`), `Y` for the region's own result, and a `Y` family mirroring the `X` one (`IY`, `OY`, `EY`, `VY`). They are declared once, at the end of the object, and no other file redeclares them.
- A `*With` variant means "the caller's continuation is fused into the node this builds", both for operations and for regions (`ArrowEffect.suspendWith`, `ArrowEffect.handleContWith`, `ArrowEffect.handleLoopWith`, `ArrowEffect.handleLoopStateWith`).
- `answering` answers one operation and returns; `answers` is the per-site loop that keeps answering while the next operation belongs to the same effect; `running` answers one operation for a loop region that is not at the top of the stack (`Handler.ContHandler.answering`, `Handler.LoopHandler.answers`, `Handler.LoopHandler.running`).
- Node classes are abstract so each construction site implements the members anonymously and keeps its own types, which is what stores a primitive input unboxed; a concrete node is the exception and says why (`Pending.Defer`, `Pending.SuspendArrow`, `Arrow.Step`; `Loop.Done`, the exception).
- The vocabulary is fixed and a synonym is a bug: the evaluator `eval`s or `run`s and never "drives", a continuation held in a node or taken by a clause is a `cont`, a handler's body is a clause, and a stack entry a handler installs is a region (`Eval.apply`, `Pending.Defer`'s `contA` and `contB`, `Handler.ArrowHandler.run`).

### Frames

An arrow the kernel mints with no user site reports `Frame.internal`, and the trace builder skips exactly that value (`Arrow.Id.frame` and `Arrow.Chain.frame`; `EffectTrace.Builder.frame`). When the kernel composes a `map` on the user's behalf it passes a frame explicitly rather than summoning one at the site: the evaluator hands the suspension's own frame to the answering entry, and the inline template carries it through to the `map` it builds, while the plain fallback uses `Frame.internal` for that `map` and keeps the operation's frame for the trace (`Handler.answersLoop`, `Handler.LoopHandler.answers`).

### Errors

A state the kernel's own invariants rule out raises `bug`, never an ad-hoc exception (`Eval.unhandled`, `Eval.unanswerable`, `Eval.guarded`, `Context.unbind`, and the `bug.failTag` extension). The module's one user-facing exception is a `KyoException` with `NoStackTrace` in a file of its own, thrown where a bracket refuses re-entry into a scope it already released, with the message spelling out both shapes that cause it (`kyo.Closed`, raised from `Bracket.region`'s `reenter`).

### The concession pattern

A deliberate departure from the module's own rules names what forced it, the smallest scope it is confined to, and what keeps it unreachable from user code. The worked case is the answering templates, whose in-flight input and continuation are held in local `var`s: the comment names the erasure that forces it, and the `var`s are born and die inside one expanded method (`Handler.answersLoop`, `Handler.answersLoopState`). The same shape recurs for the mutable `Stack`, which is borrowed from a per-thread pool and cleared on release rather than shared (`Stack.pop`, `Stack.Pool`). How a concession is then covered in tests is [Covering a concession](#covering-a-concession-and-covering-a-new-construct).

Decisions with a measurable compiled footprint get a bytecode pinning test that asserts the exact method size, so a change to the number is a result to look at rather than a baseline to rewrite (`ArrowEffectBytecodeTest`, `PendingBytecodeTest`). A decision not to have something is pinned with a negative compile test (`ArrowTest`, "an arrow is not a function"), and the module's own assertion for one requires the compiler's actual message rather than accepting any rejection (`Test.typeCheckFailure`).

## Extension recipes

### The two extension points, and the ceiling above them

`Effect`'s constructor is `private[kernel]`, so `ArrowEffect` and `ContextEffect` are the only effect kinds a contributor can define; a new effect subclasses one of those two, never `Effect` (`Effect`). The internal layer is sealed to match: `Pending` is a sealed trait and every node kind is a class in its companion, so a new capability is composed from the existing kinds and can never be a new one (`Pending`); `Handler` is a sealed `private[kernel]` class, so `Handler.ContHandler`, `Handler.MaskingHandler`, `Handler.LoopHandler`, `Handler.LoopStateHandler` and `Handler.ContextHandler` are the only handler kinds (`Handler`); and `Arrow` is a sealed trait whose implementation traits are `private[kyo]`, so `Arrow.apply` and `Arrow.recursive` are the only ways to build one (`Arrow`).

Some of the surface is `private[kyo]` and stays that way: `ArrowEffect.handleFirst` and `ArrowEffect.handleFirstRepeated` answer one operation and carry the remainder out of the region as a value, for the stream pipes (`Poll`, `Pipe`, `Sink`, `Batch`, `Stream.zip`, `Emit.runFirst`) and for `Choice.runStream`; `ArrowEffect.handleMasking` hands the clause the suspended operation itself rather than its input, and exists for `ArrowEffect.Mask` (`ArrowEffect.FirstSuspended`, `ArrowEffect.handleMasking`); `Isolate.internal.Contextual` is `private[kernel]` and reached only through `Isolate.crossing`, at the sites that leave one fiber for another. `Nested` and `Eval` are `private[kyo]` objects carrying `@publicInBinary`, and `Safepoint`'s companion is public with `private[kyo]` members, for exactly one reason, that inline expansions in downstream modules name them, and that is not an invitation to use them (`Nested`, `Eval`).

### Recipe: add a new ArrowEffect

1. Declare `sealed trait E[...] extends ArrowEffect[Input, Output]` at the top of its own file. `Var[V] extends ArrowEffect[Const[Op[V]], Const[V]]` and `Emit[-V] extends ArrowEffect[Const[V], Const[Unit]]` are the two worked examples (`Var`, `Emit`).
2. Add operation methods in the companion calling `ArrowEffect.suspend` or `suspendWith` with `Tag[E]`. Each is `inline`, takes `Tag[E]` before `Frame` in the `using` clause, and delegates straight through with no logic of its own (`Var.set`, `Emit.value`). The exception is a method that leads with `(using Frame)` so its remaining type arguments can be applied partially, and then takes the `Tag` last (`Var.use`).
3. Add `run*` handlers calling one of the `handle*` variants (see the discriminator below).
4. Optionally add an `isolate` object or a `given isolate`.

`suspend` leads with the operation's type argument, then takes `(effectTag, effectInput)` and produces `O[A] < E`; that leading `[A]` is what carries a non-`Const` operation's element type, and it is why every call site spells it, `ArrowEffect.suspend[Any](tag, input)` at its plainest (`ArrowEffect.suspend`).

| Situation | Use | Example |
|-----------|-----|---------|
| Both `Input` and `Output` are `Const`, so nothing depends on the type argument | `suspend[Any]` | `Emit.value` |
| `Input` or `Output` is a genuine type constructor | `suspend[A]` with the real element type | `Choice.evalSeq`, whose row is `Seq => Id`, and `Choice.drop`, which suspends at `Nothing` |
| The answer is consumed immediately by a known function | `suspendWith`, which fuses the suspension and its continuation into one step so the call site stays one allocation | `Var.use`, `Abort.error` (`ArrowEffect.suspendWith`) |

### Recipe: choose and write the handler

The handling variant is chosen by what the clause needs; each `handle*` scaladoc states its own discriminator (`ArrowEffect.handleCont`, `ArrowEffect.handleLoop`, `ArrowEffect.handleLoopState`):

| The clause needs | Variant | What the clause answers with | Worked example |
|------------------|---------|------------------------------|----------------|
| The continuation in hand, to apply once or not at all | `handleCont` | the region's own result type, built by applying the continuation | `Check.runAbort`, which never resumes |
| The continuation in hand, to apply more than once (backtracking, non-determinism) | `handleContRepeated` | the same, with the regions dumped into the continuation held past each application | `BracketTest`'s multi-shot suite; `handleFirstRepeated` is the peeling sibling, used by `Choice.runStream` |
| To answer each occurrence, no state between them | `handleLoop` | a `Loop.Outcome`, where `Loop.continue(answer)` carries the answer to the operation and `Loop.done(v)` ends the region | `Emit.runDiscard` |
| To thread state between occurrences | `handleLoopState` | a `Loop.Outcome2`, `Loop.continue(nextState, answer)` | `Var.runWith`, where the state is the variable |
| The region's result consumed by a known continuation | the `*With` form (`handleContWith`, `handleLoopWith`, `handleLoopStateWith`) | the same as the base form; the continuation is fused into the region node instead of mapped over it | `ArrowEffect.handleContWith` |
| To complete with the body's own value | the form without a `done` clause, which delegates to the form with one | the same | `ArrowEffect.handleCont`, `ArrowEffect.handleLoop` |
| To answer a failure of the handled body | the three-clause overload that adds `recover: Throwable => Maybe[B < (S & S2)]` | a replacement result, or `Absent` to let the failure propagate | `ArrowEffectTest`'s "recover, ported from catching" |

The `recover` overloads are the one place in the file where `v` is taken **by name**, unlike every sibling: the body is forced inside the recovery clause, so a throw while building it is the region's to answer (`ArrowEffect.handleCont`, `ArrowEffect.handleLoop`, `ArrowEffect.handleLoopState`).

Every region combinator carries the row as a pair, `S` for the body's row and `S2` as a free variable for whatever the clause adds; the scaladoc names introducing new effects through `S2` as the point of the parameter. With a single row the typer would commit it to the body's row before the clause is seen, so a clause that introduces its own effect (`Abort` in `Check.runAbort`, the fold function's row in `Emit.runFold`) could not widen it. A new region combinator keeps the pair (`ArrowEffect.handleCont`).

To add a new `handle*` variant to `ArrowEffect`, build a `Pending.HandleArrow` (or `Pending.HandleArrowWith` for a `*With` form) whose `handler` is an anonymous `Handler.ContHandler`, `Handler.LoopHandler` or `Handler.LoopStateHandler`. The `Cont` kinds need only `tag`, `run` and `done`. The loop kinds additionally override `answers` with the matching inline template from `Handler`, `Handler.answersLoop` for `handleLoop` and `Handler.answersLoopState` for `handleLoopState`, so the clause is statically bound inside the walk (`ArrowEffect.handleLoop`, `ArrowEffect.handleLoopState`).

Two traps here:

- **Omitting the `answers` override on a loop kind still compiles and is still correct**, because the base implementation in `Handler.LoopHandler` runs the clause through a virtual call, so the loss is silent: consecutive same-tag answers stop fusing inside one compiled method. Every loop variant currently in `ArrowEffect` overrides it, the `recover` and `*With` forms included; a new one that forgets is the case to watch for (`Handler.LoopHandler.answers`, `Handler.answersLoop`).
- **A `Loop` clause that defers before continuing ascribes its resumed value at the region's row**, `Loop.continue(1: Int < Ask)` rather than `Loop.continue(1)`. `Loop.Continue` is invariant in the value it carries, and `Loop.Outcome` with it, so a bare value infers an outcome the region's answer type does not accept (`Loop.Continue`, `BracketTest`'s "an effectful loop clause resuming after the pop completes the bracket").

### Recipe: tag choice, and when to erase it

Both kinds of dispatch resolve by tag subsumption, and in the same direction: the handler's or the binding's tag must be a **subtype** of the tag being sought. `Stack.find` walks from the innermost region outward and takes the first handler whose tag is a subtype of the suspension's, so a handler at a subtype effect answers an operation suspended at its supertype and a handler at the supertype leaves a subtype operation in the row (`Stack.find`, `StackTest`'s "a subtype handler resolves a supertype suspension tag" and "a supertype handler does not resolve a subtype suspension tag"). `Context.get` walks the bindings the same way, so a read takes the innermost binding whose tag is a subtype of the read's, exact or not (`Context.get`, `ContextTest`'s "a read at a supertype"). Neither test is equality, and neither relates two instantiations of one effect at different type arguments, which is how one effect at many type arguments becomes separate handlers and separate names.

- When an effect's type parameter must not gate matching, add a private `erasedTag[X]: Tag[E[X]] = Tag[E[Any]].asInstanceOf[Tag[E[X]]]` and use it at every suspend and handle site. `Abort` does this so any `Abort` region catches any `Abort` operation; `Env` does it so all `Env[R]` bindings share one name and layer through `_.union(env)` (`Abort.erasedTag`, `Env.erasedTag`, `Env.run`).
- For many independently-scoped values under one effect, share one tag and make the bound value a map each binding updates rather than replaces: every `Local` binds over `Tag[Local.internal.State]`, and `Local.let` passes `_.updated(this, value)` as the `ifDefined` arm of `ContextEffect.handle`, which is what that arm exists for, deriving the region's value from the one outside it rather than replacing it (`Local.let`, `ContextEffect.handle`, `Handler.ContextHandler.derive`).

### Recipe: add a new ContextEffect

1. `sealed trait E extends ContextEffect[A]`.
2. Reader methods calling `ContextEffect.suspend` or `suspendWith` with the tag.
3. A `run`-style method calling `ContextEffect.handleInheritable(tag, value)(v)`, or `handleInheritable(tag, ifUndefined, ifDefined)(v)` when the region derives its value from the one outside it.
4. `ContextEffect.handle` instead, when the region needs its own fork and join strategies. `handle` is not `handleInheritable` with defaults filled in: it puts the tag alone in the first parameter list and makes `fork` and `join` required, and `handleInheritable` is defined as the call to it that inherits (`fork = parent => parent`, `join = (parent, _, _) => parent`).

`Env.run` (erased tag, `_.union(env)` as `ifDefined`) is the worked `handleInheritable` example; `Scope.run` is the worked `handle` example, deriving its finalizer from any enclosing one, forking to `parent.forked`, and joining by keeping the parent's (`Env.run`, `Scope.run`).

`ContextEffect.handle`'s edge parameters are the whole binding-lifecycle extension surface. `derive` computes the region's value from the outer one, absent when no outer handler provides one; `fork` is what a forked computation receives and `join` is what the binding holds once a fork ends, and keeping this one, taking the fork's, or merging them is the whole of an isolate strategy. Only those three are required. `done` runs when the region's extent ends normally and `release` when a failure unwound it, both `Unit`-returning with no-op defaults, so a binding that owes nothing pays nothing; the call shapes are `done = (v: A) => ...` and `release = (v: A, ex: Throwable) => ...` (`ContextEffect.handle`, `ContextEffectTest`'s "completion and release").

Reach for the two-argument `ContextEffect.suspend(tag, default)` overload when the value should be optional: it returns `A < Any`, so a reader with a default names no effect at all. `Local.get` and `Local.use` both use the `suspendWith` form of it (`ContextEffect.suspend`, `Local.get`).

**`ContextEffect.handle`'s `fork` is `A => A`, so a binding it installs always crosses a fork**; there is no marker type, annotation, or `Absent` to opt out with at the kernel level. An effect that wants a per-value opt-out builds it above the kernel out of the value it binds: `Local` binds a map, gives each `Local` its own `fork: A => Maybe[A]`, and drops the `Absent` ones when the kernel's `fork` runs over the map, which is what `Local.initNoninheritable` spells (`ContextEffect.handle`, `Local.scoped`, `Local.initNoninheritable`).

### Recipe: add an Isolate

An isolate for a new effect implements two type members and three phases: `type State`, `type Transform[_]`, `capture` (read the state where the fork happens), `isolate` (run the body handled, producing `Transform[A]`), `restore` (write it back). `Var.isolate.Base` and `Emit.isolate.merge` are the two worked examples, and for one effect only `restore` differs between strategies (`Var.isolate`, `Emit.isolate.merge`).

- `capture` answers at `Remove & S`, not at `S`: it reads the state through the effect being isolated, so the reading itself is an operation of that effect. The `IOTask` integration relies on that row, and the inline comment on `Isolate.capture` says so (`Isolate.capture`, `Fiber.initUnscoped`).
- An effect with one obvious policy exposes it as `given isolate: Isolate[E, Any, E]` in its companion so derivation picks it up without a `use` block; `Check` writes the instance inline, `Memo` delegates to `Var.isolate.merge` (`Check.isolate`, `Memo.isolate`).
- **Do not provide an isolate for a short-circuiting effect.** Derivation composes instances in the order the effects appear, so the result would depend on which one is handled first (`Isolate`'s scaladoc, the "Important" note).
- A `ContextEffect` needs no isolate instance of its own: `Isolate.internal.deriveImpl` drops every `ContextEffect` from the `Remove` row before summoning, because context bindings cross through `Isolate.internal.Contextual`, which a spawn composes in front of the caller's isolate through `Isolate.crossing`. Materialization flattens the `Remove` intersection, drops the `Keep` and `ContextEffect` members, summons an instance per remaining effect, and folds them onto `Isolate.internal.Identity` with `andThen`. `Identity` is the fold base, not `Contextual`: an isolate asked for in place forks nothing (`Isolate.internal.deriveImpl`, `Isolate.internal.Identity`).
- Naming `Region.NoEscape` in the row is refused before `Keep` is subtracted, with its own message: the continuation a clause received carries the regions between the handler and the suspension, so it cannot be forked, raced, timed out, or sent to another fiber. The message points the reader at answering with it in place or moving its values across through a `Channel` (`Isolate.internal.deriveImpl`, `Isolate.Disallowed`, `Region`).
- A missing isolate is a compile error carrying a four-option teaching message (handle the effect first, use the effect's `isolate` object, compose with `andThen`, or write a custom instance); that message is the contract a new effect's isolate story is judged against (`Isolate.internal.deriveImpl`).
- `Isolate.andThen` short-circuits on `Identity` on either side, which is what makes `Identity` a usable fold base, and composes everything else pairwise: `State` becomes the pair, `Transform` nests, and `restore` runs `next` outside `self` (`Isolate.andThen`).
- `Isolate.run(state, v)` is the one combinator on `Isolate` left non-final where `run(v)`, `apply`, `use`, `andThen` and `crossing` are all `final`, so `restore(isolate(state, v))` is its meaning rather than its required implementation and an instance that can cross without building a `Transform` may replace it (`Isolate.run`).
- `Isolate.nest` returns `A < Restore < (Remove & Keep & S)` and builds that nesting with `Nested.nest`, the internal boxing, because the implicit lift's `CanLift` guard rejects a syntactically pending type at a direct ascription. `Kyo.lift` is the public spelling of the same move. Copy the shape rather than simplifying it (`Isolate.nest`, `Nested.nest`, `CanLift`).

### Recipe: mask an effect between two points

Masking lives inside `ArrowEffect`, as `ArrowEffect.Mask`, and package `kyo` does not export `ArrowEffect`, so a caller outside `kyo.kernel` needs `import kyo.kernel.*` or `import kyo.kernel.ArrowEffect.Mask`. `Mask[S]` is itself an `ArrowEffect` whose input is a whole pending computation (`sealed abstract class Mask[S] extends ArrowEffect[[A] =>> A < S, Id]`), so a masked request travels to `Mask.run` as an unevaluated payload and is re-raised there (`ArrowEffect.Mask`, `Pending.Suspend.reraise`).

1. Wrap with `Mask[E](v)`, naming the effect explicitly; the type argument is not inferred (`ArrowEffect.Mask.apply`).
2. Install the local handlers over the masked value.
3. Unmask with `Mask.run[E](...)` at the boundary where the outer handlers should see it (`ArrowEffect.Mask.run`, `ArrowEffectMaskTest`).

Masking is selective by construction: every other effect in the row stays visible to the local handlers, and the outer answer flows back into the masked computation, pinned end to end (`ArrowEffectMaskTest`'s "masking is selective").

`Mask` covers **both** effect kinds. Its bound is `E2 >: E <: Effect`, not `<: ArrowEffect[I, O]`, and the call needs `Tag[E2]` plus `Tag[Mask[E]]`. An arrow operation reaches the clause by the stack lookup; a context read reaches the same clause because entering the region masks the tag in the context, so the read dispatches to the region instead of answering from the binding outside it. One `Mask[Ask & Cfg]` covers an arrow effect and a context effect at once (`ArrowEffect.Mask`, `Handler.MaskingHandler`, `Context.mask`, `ArrowEffectMaskTest`'s "context effects" section). The clause is handed the request itself rather than an input, which is why the underlying `ArrowEffect.handleMasking` exists as a separate `private[kyo]` variant.

### Recipe: add to the kernel's own surface

- **A new public inline entry point** gets a case in `outsidekyo/KernelTest.scala` that both compiles and runs it: compiling proves the name resolves from outside package `kyo`, running proves the accessor the compiler emitted for it is well formed (`KernelTest`, in `outsidekyo/KernelTest.scala`). That suite extends ScalaTest's `AnyFreeSpec` directly rather than the module's `kyo.Test`, which lives in package `kyo`. `Implicits.abortCastUnit` is the one deliberate omission, since it exists to fail compilation.
- **A new platform-specific member** is defined in both `jvm-native/.../internal` and `js-wasm/.../internal` with an identical member surface and identical visibility, differing only where the platform forces it. `Safepoint` and `Report` are the two worked pairs, and they are the only two (`Safepoint`, `Report`).
- **A new internal class in the interpreter path** needs nothing: `EffectTrace.isPlumbing` filters by the `kyo.` class-name prefix, so anything in the package is dropped from a user-visible stack trace without a list to maintain (`EffectTrace.isPlumbing`).
- **Diagnostics go through `Debugger`**, an abstract class with identity defaults and one installed instance via `install` / `uninstall` / `get`. Every call site is `inline if Debugger.enabled`, a `CompileTimeFlag` defaulting to false, so the hooks compile away when it is off; a new hook follows that shape. Real subclasses live under `kyo-kernel/jvm/src/main/scala/kyo/kernel/debug/`, a JVM-only main source root, not in the shared kernel (`Debugger`, `ConsoleDebugger`, `DebugSession`).

### Traps a new effect hits

- **A multi-shot clause over a body holding a bracket is refused at the second branch with `kyo.Closed`**: the resource was released when the first branch completed, and re-entering its scope would read what is gone. The refusal comes from the bracket's own region, whose `reenter` hook throws with a message naming both ways out, acquiring inside the branch or putting the bracket outside the handler. `handleFirst` inherits it, its remainder being one-shot for the same reason (`Bracket.region`, `BracketTest`'s "multi-shot clauses" section).
- **The way out is declaring the clause repeated**, `handleContRepeated` or `handleFirstRepeated`, which holds the regions dumped into the continuation so they discharge once where the handler ends rather than at whichever resumption finishes first. Only for a clause that really does resume more than once: holding keeps the obligation longer than a single-shot clause needs (`ArrowEffect.handleContRepeated`, `Handler.repeated`).
- **An effect whose `Output` is itself a pending computation** (`ArrowEffect[Const[Unit], [X] =>> Int < Say]`) cannot hold that computation through a direct ascription: the implicit lift's `CanLift` guard rejects syntactically pending types. `Kyo.lift` is the public way through, taking no `CanLift`, and the answer then crosses the handler's walk unopened (`ArrowEffectTest`'s `AskBoxed`, `Kyo.lift`, `CanLift`).

## Cross-platform

Only two main-source files are platform-specific, and each has exactly two copies, one under `jvm-native/` and one under `js-wasm/`: `Safepoint.scala` and `Report.scala`. One more main source root is platform-specific without a counterpart, `jvm/src/main/scala/kyo/kernel/debug/`, which holds the `Debugger` subclasses. Everything else in the module is in `shared/`, `Stack` and `Eval` included.

| Concern | jvm-native | js-wasm |
|---------|-----------|---------|
| `Safepoint` | A global open-addressed slot table keyed by thread id, holding a depth-guard budget and armed bit per slot and a stop sentinel for cross-thread preemption (`Safepoint.home`, `Safepoint.slots`) | Three module vars, because preemption is a slice deadline rather than a cross-thread sentinel: the packed depth-guard budget and armed bit, a deadline, and a stop flag that stands until the slice boundary consumes it (`Safepoint.depth`, `Safepoint.stopRequested`) |
| `Report.unhandled` | Routed to the thread's uncaught-exception handler | Printed, there being no thread to route to |
| Static members | `@static` on the object's own boundary primitives, `get` / `enter` / `exit` and the slot table they read | Plain module members; the `period` flag's validator is a top-level private object rather than a lambda in the object body |

The two `Safepoint` variants must expose an identical member surface, visibility included, because shared inline expansions (the value lift, `Effect.deferInline`, `Arrow.apply`) name those members from downstream modules, and `Fiber`, `Sync` and `IOTask` name them outright. Only the private helpers differ (`Safepoint`).

The directory names are load-bearing for the build. `jvm-native/` and `js-wasm/` are the build's partially-shared directories, named by joining platform identifiers with a dash, and the build tooling maps a changed file under one of them to exactly those platforms' projects (`TestKyo.fileToProjects`). Stacks come from a per-thread pool, but the pool is shared source, a plain `ThreadLocal` reached through `Stack.borrow` and `Stack.release`, so an eval allocates no stack of its own in steady state and nothing about it is platform-specific (`Stack.borrow`).

Per-platform test roots follow the same split: `jvm-native/src/test` holds the threading suites plus the physical-trace and `Report` suites, `js-wasm/src/test` holds its own `SafepointTest`, and `jvm/src/test` holds the bytecode-shape pins (which need javassist) and the two concurrency suites. JVM test parallelism is off because the safepoint slot table is global, and the build says so at the setting (`build.sbt`, the `kyo-kernel` project's `jvmSettings`). The JVM project is also the only one carrying benchmarks: `jvm/src/jmh` holds `KernelBench` and `CompileBench` plus cross-framework comparisons whose libraries are jmh-scoped so they never reach the compile or test classpaths.

## Testing

### The base, and why it is not kyo-test

Kernel suites run on ScalaTest, never on kyo-test. The reason is observer-outside-observed: the kernel sits under every other module including the test framework, so kyo-test would run these leaves as fibers on the scheduler the kernel powers, and that scheduler's preemption writes into the stop channel and safepoint state the suites assert on. A harness exemption cannot close it, because combinators respawn nested fibers the exemption does not reach (the scaladoc on `kyo.Test` in this module's test sources). The build carries the same rule at the `kyo-kernel` project: a plain ScalaTest `Test` dependency with that reason in a comment beside it, and no `.withKyoTest` call, while `kyo-prelude`, the first module above the kernel, does call it. `WithKyoTest`'s own scaladoc still uses `kyo-kernel` as its usage example; copying that example would undo the rule (`project/WithKyoTest.scala`, the `Example:` block).

A suite extends the module-local `kyo.Test` when it carries negative-compile assertions: it is an `AnyFreeSpec` with `NonImplicitAssertions` that adds one helper, and the six suites on it (`KyoTest`, `PendingTest`, `ArrowEffectTest`, `IsolateTest`, `ContextTest`, `CanLiftTest`) all spell it as bare `Test`, reached by `import kyo.*` from outside package `kyo` and by package membership inside it. Every other suite extends `org.scalatest.freespec.AnyFreeSpec` directly.

- There are no matchers anywhere in the corpus: no `===`, no `shouldBe`. The vocabulary is `assert`, `intercept`, `succeed`. `NonImplicitAssertions` enforces it for the suites on `kyo.Test`; the rest hold to it by convention (`IsolateTest`, "creates an isolate for context effects").
- `Test.typeCheckFailure(code)(expected)` is the module's negative-compile assertion. It fails when `code` compiles, and otherwise fails unless the compiler's message contains `expected`, which must be nonempty. A rejection is pinned to the real message text rather than to "it did not compile" (`PendingTest`, "eval should not compile for pending effects"; `ArrowEffectTest`, "a continuation cannot cross an isolate boundary"). This is the same substring-match contract the root guide describes for kyo-test's helper; the module-specific part is that kyo-kernel keeps its own copy, for the same layering reason it does not run on kyo-test at all.
- Opaque kernel types have no `==`. `Safepoint.State` and `Safepoint.Slot` are opaque `Int`s, so a depth or budget assertion goes through `.equals` (`EvalTest`, "a throw escaping a root eval leaves the safepoint depth unchanged"), and the slot-identity suite declares a local `CanEqual` with a comment saying why (`SafepointConcurrencyTest`, the `given CanEqual[Safepoint.Slot, Safepoint.Slot]`).
- Render pins embed `file:line:col` from the frame, so inserting or deleting a line anywhere above one breaks its expected string. The comment on the case says so, and says the strings are re-read from the failure rather than recomputed (`KyoTest`, "toString").

Two conventions to follow, one of which the corpus does not yet follow everywhere:

- **New negative-compile assertions use `Test.typeCheckFailure`**, which pins the message. Four suites still carry unpinned rejections: `ImplicitsTest` declares its own private `typeCheckFailure` doing the substring check by hand and elsewhere asserts only `typeCheckErrors(...).nonEmpty`, and `PendingTest`, `ArrowEffectTest` and `EvalTest` each have a bare `assertTypeError` site, which accepts any rejection.
- **A suite that needs the safepoint period reads it from `Safepoint.period()`**, because 512 is only the default of an overridable `StaticFlag` (`kyo.kernel.internal.maxStackDepth`, feeding `Safepoint.period` in both platform copies). The corpus follows this everywhere and no test hardcodes the number: `PendingTest`, `ArrowEffectTest`, `SafepointTest` and `SafepointConcurrencyTest` each bind `private val Period = Safepoint.period()`, and `EvalCaptureTowerTest` derives its `Reach` from it.

### Naming, placement, fixtures

- Test files are 1:1 with the source they cover, and a split carries a closed-vocabulary aspect suffix naming why it is separate: `Threading`, `Bytecode`, `Concurrency`, `Physical`, `UnstartedThread`, `CaptureTower`, `Mask` (`ArrowEffectThreadingTest`, `ArrowEffectBytecodeTest`, `SafepointConcurrencyTest`, `EffectTracePhysicalTest`, `SafepointUnstartedThreadTest`, `EvalCaptureTowerTest`, `ArrowEffectMaskTest`).
- The bar for leaving `shared/` is that the case is not expressible or not portable there, never that the platform infra is inconvenient. What forces each file out is legible from what it does: a raw `new Thread` and a cross-thread `Safepoint.stop` in the `Threading` suites, javassist in the `Bytecode` suites, virtual threads and `CountDownLatch` gates in `SafepointConcurrencyTest`, an unstarted `Thread` in `SafepointUnstartedThreadTest`.
- Stating that reason in a scaladoc header on the out-of-`shared` file, and back-pointing to it from the shared sibling that keeps the rest, is the convention to follow on a new file. No existing out-of-`shared` file carries such a header and no shared file carries the back-pointer, so the corpus has yet to be brought up to it.
- Per-suite fixtures are declared inline as a `sealed trait` effect plus a suspend helper plus an `answerAsk`-style handler, rather than pulled from a shared base class (`EffectTest`, the `Ask` / `ask` / `answerAsk` trio; `EvalTest` and `BracketTest` repeat the shape). When two suites need the same fixture it goes into a plain object in a sibling test file, not into `Test`: `KyoForeachTest.scala` holds only `object KyoForeachTest` with the effects `KyoForeachCollTest` imports.
- The park driver is internal, and any suite that parks reaches for it: `Eval.partial`, `Eval.release`, `Pending.Park` and `Safepoint` appear throughout the `kyo.kernel` suites, not only the `kyo.kernel.internal` ones, because the kernel has no `Async` to park with. What stays confined to the internal suites is direct construction of the interpreter's own units, `Stack` and `Handler` (`StackTest`, the hand-built `Handler.LoopHandler` fixtures).
- `@TestVariant` is live in kyo-kernel: the annotation class is copied into the module's test sources and the sbt source generator is wired in the `kyo-kernel` project's shared settings, so `KyoForeachCollTest` compiles and runs the `List` and `Chunk` variants the annotation names alongside the `Seq` base.

### Deterministic timing without a clock

The kernel sits below `Async`, `Channel` and `Fiber`, so the root guide's barrier primitives are unavailable here. The replacements:

- A `private def requestStop()` declared per suite is the park driver: it takes the slot, lodges a stop against the current thread, and sets a deadline already in the past. Both halves are there because the two `Safepoint` copies deliver preemption differently, a dispatched stop on jvm-native and a slice deadline on js-wasm, and both expose both members, so the one helper parks on either platform (`BracketTest`, `EvalTest`, `ArrowEffectTest`, `DebuggerTest` and `ArrowEffectMaskTest` each carry a copy).
- A park test asserts the three-part shape: the slice parked (`Eval.partial` returns a `Pending.Park` whose `evalNow` is empty), nothing was released or committed at the park, and the resumed eval yields the full value (`BracketTest`, "releases when a parked remainder is abandoned" and "a resumed parked bracket completes and releases with Absent"; `EvalTest`, "parks on a pending stop and the parked value resumes to the same answer").
- `drainedBudget` forces the budget-denied arm deterministically by draining the slot's budget under a save/restore pair, so the deferral path is exercised without running a full period of steps (`PendingTest`, the `drainedBudget` helper and the nested-value cases under it).
- Cross-thread coordination is a `@volatile` readiness flag spun on, then a bounded `join`, then an assertion that the thread actually ended; there is no `Thread.sleep` anywhere in the module's tests (`EvalThreadingTest`, "a cross-thread stop parks a settled spin with no suspensions"; `EffectThreadingTest`, "a cross-thread stop parks inside a bracket and abandonment releases"). The JVM concurrency suite factors the wait into one deadline-bounded `spinUntil` helper, and the slot-table cases that need thousands of live threads use virtual threads plus `CountDownLatch` gates (`SafepointConcurrencyTest`, the `spinUntil` helper and "the overflowed slot ignores budget operations and misses preemption").
- Where the landing point of a stop is not exactly determined, the assertion is a tight bounded range carrying the observed value as its failure clue, never a loose "it eventually parked" (`ArrowEffectTest`, "a stop arriving during eager construction inside a slice reifies and parks the chain"; `EvalThreadingTest`, "a preemption stop reifies and resumes with handler state", both pinning the count to a two-wide window). A genuinely probabilistic delivery is made reliable by repetition, and what it asserts is the conservation law rather than a count (`EffectThreadingTest`, "an abandonment racing a resume releases exactly once", two hundred iterations; `SafepointConcurrencyTest`, "racing stop requests never lose the slot ownership", eight threads times a thousand requests, asserting consumed never exceeds requested).
- `Eval.release` is how abandonment is run deterministically after a park, including in the abandon-versus-resume race (`BracketTest`, "releases when a parked remainder is abandoned"; `EffectThreadingTest`, "an abandonment racing a resume releases exactly once").
- Unbounded stack growth is made observable by running the scenario on a thread with an explicit small stack (256 KB) rather than by inspecting frames (`ArrowEffectThreadingTest`, "deep state transitions under a suspending clause fit a small stack"). Stack-safety pins assert a concrete result at a named depth, 1M through maps, 100k through a suspension, 10k through a mask, never merely "no exception" (`EvalTest`, "a long map tower evaluates in bounded stack" and "deep sequential operations are stack safe"; `ArrowEffectMaskTest`, "deep masked operations are stack safe").
- Safepoint state is process-global (a per-thread slot in a shared table), so a suite must leave the slot as it found it, with an explicit save/restore or a `finally` exit pair (`PendingTest`, the `drainedBudget` helper; `SafepointTest`, "the budget flows through enter, exit, save, and restore"). JVM test parallelism is off for the whole module for the same reason: the overflow suite fills the global slot table and would degrade any concurrently running suite's threads. The `Debugger` suite has the same shape of problem and installs its process-global session through a `session` helper that uninstalls in a `finally`, with a synchronized buffer behind its recording hooks (`DebuggerTest`, the `session` helper and the `Recording` debugger).

### Covering a concession, and covering a new construct

When a change concedes interpreter mutability, the corpus opens a section named for the mechanism conceded to, and each leaf under it names the hostile axis it applies rather than the construction the mechanism was built for (`ArrowEffectTest`, "the answer fast path" and "the cont answer fast path"). The axes are the same four for every such concession, applied to both dispatch lanes: multi-shot replay of a capture, a full nested eval run inside a clause, a throw mid answer loop, and a park taken mid answer loop ("a capture across the fast path is multi-shot, including across threads", "a clause can run a full eval of its own mid-loop", "a throw after settled answers recovers with every commit already made", "a park taken mid answer loop resumes in a fresh full eval", plus the cont-lane mirror of each). A multi-shot pin replays the capture at least twice on the calling thread; the cross-thread half is a literal mirror in the jvm-native file, same body, resumed on a `new Thread`, so the two files can be diffed against each other (`ArrowEffectThreadingTest`, "a capture across the fast path replays on another thread" and "a hoarded fast-path continuation replays on another thread after the region finished"). A throw-recovery axis asserts exactly which commits survived, by recording every clause run into a `ListBuffer` and comparing the full list. `"audit pins"` sections hold the adversarial cross-lane cases (`ArrowEffectTest`, "safety audit pins" and "reading audit pins"; `BracketTest`, "reading audit pins"), and where the reason for a case is not legible from its name a comment states the law it defends rather than the code path it walks.

Cover a new cross-cutting construct the way `ArrowEffectMaskTest` covers `ArrowEffect.Mask`: first the base semantics (one operation, every operation, an operation outside the construct, selectivity against a second effect), then an `"interactions" -` block crossing it with each kernel mechanism, then an independence case for two instances of the construct ("masks of different effects stack independently"). The interaction checklist is fixed: bracket release on the answered path, bracket release when the outer handler discards the continuation, a recovering region across the construct, a stateful local handler threading state through it, a multi-shot outer handler replaying it, deep stack safety, and idempotence of double application. Effect-order assertions are exact ordered lists, built by prepending into a local `var` and reversing or by appending into a `ListBuffer`, never bare counters, and a multi-shot interaction asserts both the composed result and the local effects each replay produced ("a multi-shot outer handler replays the masked region and its local effects").

Double-nesting (a computation held as data, boxed twice) is pinned in its own case at every layer that can see it: the representation, evaluation, and the budget-denied arm (`NestedTest`, "boxes an already-boxed value again, one level per lift"; `EvalTest`, "double nesting round trips one level per eval"; `PendingTest`, "a doubly nested value denied by the budget strips exactly one level under map").

### The safepoint contract pins

`SafepointTest` is where the stop channel's contract lives, and a change to preemption is judged against it: a delivered stop is consumed exactly once and a second `stop` while one is pending is idempotent rather than additive ("stop wraps the slot and stopped consumes it once", "a second stop while one is pending is idempotent"); an addressed stop is honored only while its slice runs, with the stale sentinel taken out so the channel is clean for the next request ("an addressed stop is honored only while its slice runs", "the slice boundary drops its own late stop"); a stop addressed to a departed slice must not short-circuit the next evaluation, pinned by running a 100-step chain to completion ("a stop addressed to a departed slice does not short-circuit the next evaluation"); and the budget is pinned as an exact count, `enter` succeeding exactly `Period` times before denying, with `reset` and `restore` returning the slot to a usable state ("the budget flows through enter, exit, save, and restore").

### Reproduction-first discipline in the corpus

- A regression test carries its provenance above the case: the issue number, the symptom, and why it was invisible (`EvalTest`, the `#1820` comment over "a release waiting on a value that already arrived is found on abandonment"). Where the issue number alone identifies the bug, it goes in the leaf name (`EffectTraceTest`, "bug #1172 null frames").
- A group of cases sharing one root cause is introduced by a block comment naming the cause in prose, so the tests read as one diagnosis rather than several unrelated cases (`EvalTest`, the comment opening the abandonment-release cases; `BracketTest`, the comment opening "multi-shot clauses").
- Where the property a case pins is split across suites, the comment says which suite owns the other half rather than leaving it to be rediscovered (`EvalTest`, "release reports the first operation", whose comment routes the release half to `BracketTest`).
- A comment on a case states the law it defends, not the code path it walks (`BracketTest`, the comments over the `handleFirst` remainder cases; `ArrowEffectTest`, the comment on the `kyo.IsFatal` case, which says what asking `NonFatal` instead would cost).
- No probe or scratch test file ships: every file under `jvm/src/test` is named after the source it pins (`ArrowEffectBytecodeTest`, `PendingBytecodeTest`, `DebuggerBytecodeTest`, `EvalConcurrencyTest`, `SafepointConcurrencyTest`).
- A bytecode-size pin is an exact `Map` equality carrying the observed map as its failure clue, with a comment where the number needs one (`ArrowEffectBytecodeTest`, "handleCont", whose comment records that `Region.NoEscape` is a type and so costs no bytecode).
- The `suspend` / `suspendWith` / `handleCont` compiled size at a user call site is pinned by test at 14 / 14 / 48 bytes: what every user call site expands to, where a size that moves is a result to investigate, never a baseline to rewrite (`ArrowEffectBytecodeTest`, "suspend", "suspendWith", "handleCont").

## Checklist: adding a new X to kyo-kernel

Run this before writing code.

1. **Is it an effect?** Then it subclasses `ArrowEffect` or `ContextEffect`, never `Effect`, whose constructor is `private[kernel]` (`Effect`).
2. **Is it a new node, handler kind, or `Arrow`?** Not from outside the kernel. All three hierarchies are sealed and every implementation of each is kernel-internal; compose from the existing nodes (`Pending`, `Handler`, `Arrow`). `Abort.run` is the model for what a new capability looks like from above: one three-clause `handleCont` and no kernel change (`kyo-prelude`, `Abort.run`). `ArrowEffect.Mask` is what the other answer costs: masking needed a handler kind of its own, so it carries `Handler.MaskingHandler` and the `private[kyo]` `ArrowEffect.handleMasking`, and it lives in the kernel rather than above it.
3. **Does it touch the union?** Then discriminate `Pending` first and defer, take the budget, unnest exactly once, and return the eval's currency (`Pending.map`). Never cast in place of the lift where the payload can itself be a computation (`Loop.done`).
4. **Does it add a stack entry?** Decide whether it is a `Step` (foldable into the continuation) or a `Region` (must stay findable on the stack). A handler, binding, masking scope or bracket is a `Region`, and folding it away silently breaks the scans (`Arrow.Step`, `Stack.push`, `Stack.find`).
5. **Which handler variant?** `handleCont` for continuation-in-hand, `handleContRepeated` when the clause resumes that continuation more than once, `handleLoop` for stateless answers, `handleLoopState` for threaded state; add the `*With` form if the result feeds a known continuation, and the three-clause form if a failure of the handled computation needs a `recover` arm; keep the `S`/`S2` row pair; a loop variant overrides `answers` with the matching `Handler` template or loses the per-site answer loop silently (`ArrowEffect.handleCont`, `ArrowEffect.handleContRepeated`, `Handler.LoopHandler.answers`, `Handler.answersLoop`, `Handler.answersLoopState`). Declare the two flags the region needs: `repeated` where the clause resumes its continuation more than once, `escaping` where it hands the continuation out of the clause as a value; both default to false and both decide who owes the regions dumped into that continuation (`Handler.repeated`, `Handler.escaping`).
6. **Which tag relation do you need?** Handlers and bindings both match by subsumption on the erased tag (`Stack.find`, `Context.get`); erase the tag itself when the type parameter must not gate matching (`Abort.erasedTag`).
7. **Does it fork?** Then decide the isolate story: a `given isolate` for one obvious policy (`kyo-prelude`, `Check.isolate`), no isolate at all for a short-circuiting effect (`kyo-prelude`, `Abort`, which declares none), and nothing for a `ContextEffect`, which crosses through `Isolate.internal.Contextual` (`Isolate`).
8. **Does it own a resource?** The release runs exactly once, a park carries it rather than running it, and a resumption into an extent that already ended is refused with `kyo.Closed`, whether the second shot comes from a multi-shot clause or from a remainder consumed after its scope exited (`Bracket`, `Bracket.region`, `Eval.park`; `BracketTest`, "releases exactly once", "releases when a parked remainder is abandoned", "a multi-shot capture over a bracket refuses the second shot").
9. **Is it `inline` and public?** Then every symbol its expansion names has to resolve from outside `kyo`: a `private[kyo]` object it reaches carries `@publicInBinary` (`Eval`, `Nested`), the `Safepoint` members it names are public on both platform copies (`Safepoint.get`, `Safepoint.enter`, `Safepoint.exit`), and a conversion it depends on is public in binary rather than inline, since an inline one binds a prefix proxy at every expansion site (`` `<`.fromKyo ``). It gets a case in `KernelTest` that both compiles and runs it, since compiling proves the name resolves and running proves the emitted accessor is well formed (`outsidekyo/KernelTest.scala`).
10. **Is it platform-specific?** Then both `jvm-native/` and `js-wasm/` get a copy with the same member surface and the same visibility, differing only where the platform forces it: `Safepoint.deadline` is a no-op on `jvm-native/`, where a stop reaches a thread through the slot table, and arms a real deadline on `js-wasm/`, where there is one thread and no table (`Safepoint`, in both trees).
11. **Is it a new node kind on the interpreter path?** Then give it an arm in `EffectTrace.Builder.drain`, which walks the node families by hand; a kind with no arm contributes nothing to a trace. Nothing has to be registered for the physical half: `EffectTrace.isPlumbing` filters by the `kyo.` package prefix, so a class placed outside one leaks into user stack traces (`EffectTrace.Builder.drain`, `EffectTrace.isPlumbing`).
12. **Are you conceding a module rule?** Then say in place what forces it, the smallest scope it is confined to, and what keeps it unreachable from user code. A cast additionally names the category that makes it sound: `Nested.unnest` rather than a bare cast at a settled arm, `Erasure-forced:` where the type is existential from the site (`Eval`), a statement of why the value cannot be `Nested` where it stands in for the lift, or the liberty a widening takes. Then pin its adversarial cases in a section that says so (`ArrowEffectTest`, "safety audit pins").
13. **Tests.** The kernel tests on ScalaTest, never on kyo-test, because kyo-test runs its leaves as fibers on the scheduler this module powers; extend `kyo.Test` for the `typeCheckFailure` helper, or `AnyFreeSpec` directly (`kyo.Test`). Assert concrete values through the public surface, reach a park through `Eval.partial` after `Safepoint.stop(Thread.currentThread())` and abandonment through `Eval.release` (`BracketTest`, "releases when a parked remainder is abandoned"), leave the safepoint slot as you found it with `Safepoint.save` and a `finally Safepoint.restore` (`ArrowTest`, "defers when the budget is drained and still completes"), and put a cross-platform case in `shared/` unless it is genuinely not expressible or not portable there (`SafepointUnstartedThreadTest`, "stop misses a thread that never evaluated"). A fenced block added to the module README is compiled by `sbt kyo-kernelJVM/doctest`, which is the whole of the docs check.
14. **Did a pinned number move?** A bytecode size or a stack-safety depth that changed is a result to investigate, never a baseline to rewrite (`ArrowEffectBytecodeTest`, `PendingBytecodeTest`).
