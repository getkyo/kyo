# Contributing to kyo-kernel

Module-specific guidance for kyo-kernel, the effect system's kernel. Read the repository-root [CONTRIBUTING.md](../CONTRIBUTING.md) first: it carries the global conventions (naming, `using`-clause ordering and the `(using Frame)` type-parameter-separator pattern, `discard` for dropped results, the Unsafe Boundary tiers, the generic `Test[Any]` base-trait hierarchy, and the brief Effect Implementation Reference for `ArrowEffect`, `ContextEffect` and `Isolate`). This guide documents only what is true because of how kyo-kernel itself is built.

**The headline invariant: `A < S` is an untagged union whose three arms are told apart by runtime class alone, so a value is nested exactly once on the way in, carried opaquely in between, and unnested exactly once on the way out** (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:45`). Every other rule in this module (the evaluator's dispatch, handler answers, continuation values, the `Loop` outcome protocol) is a consumer of that single fact. One extra or one missing nesting level makes the evaluator mistake a payload for a suspension, or hands a caller a box where it expected a value (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/NestedTest.scala:8-11`). The section [Nest once, carry opaque, unnest once](#the-headline-invariant-nest-once-carry-opaque-unnest-once) is the deepest part of this guide because it is the part a change is most likely to break.

Topics the root guide already covers, followed here without amendment:

- `ArrowEffect[I, O]` as the extension point for function-like effects parameterized by input and output type constructors: root CONTRIBUTING.md, Effect Implementation Reference > Anatomy of an Effect.
- The three-phase `capture` / `isolate` / `restore` protocol of `Isolate`: root CONTRIBUTING.md, Effect Implementation Reference > Isolate Protocol for Fiber-Crossing Operations.
- Exposing multiple write-back policies as `update` / `merge` / `discard` in an `object isolate` namespace: root CONTRIBUTING.md, same section.
- The leading type-parameter list before `using Frame` for entry points that need one explicitly-named type argument: root CONTRIBUTING.md, API Design > Method Signatures.
- `discard(...)` rather than `val _ =` for an intentionally-dropped result: root CONTRIBUTING.md, Code Conventions > Scala Conventions.

A contributor arriving with a concrete task rather than reading start to finish should jump straight to [Checklist: adding a new X to kyo-kernel](#checklist-adding-a-new-x-to-kyo-kernel), which routes to the matching recipe under [Extension recipes](#extension-recipes): Recipe: add a new ArrowEffect, Recipe: choose and write the handler, Recipe: tag choice, and when to erase it, Recipe: add a new ContextEffect, Recipe: add an Isolate, Recipe: mask an effect between two points, and Recipe: add to the kernel's own surface.

Two structural facts shape everything else in the module:

- `Effect`'s constructor is `private[kernel]`, so the hierarchy fans out to exactly two kinds and no downstream module can add a third: `ArrowEffect` for suspended computations with input/output transformations, `ContextEffect` for suspended computations requiring contextual values (`kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:27-31`).
- `Arrow[-A, +B, -S]` is the module's function-like link, deliberately not a `Function1`: `Function1` is `@specialized` on both parameters, so every class mixing it in emits the whole `apply$mcXY$sp` forwarder grid, measured at 19776 definitions across this module and not one genuine call site. Handlers take an `Arrow` directly, which also spares the eval an eta-expansion per suspension (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:10-14`).

`Arrow` splits into two kinds by whether the eval's scans must be able to see the link: a `Step` may be folded away, a `Region` may not (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:101-111`). That split is the load-bearing type distinction in the representation, and [Evaluation laws](#evaluation-laws) explains what it buys.

### One operation, end to end

1. **Suspension.** An `ArrowEffect` operation allocates one `Suspend` node carrying frame, tag, input and the identity continuation. Nothing runs (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:82-86`).
2. **Region install.** `handleCont` / `handleLoop` / `handleLoopState` build a `Handle` node holding the unforced body, the handler and the region's own continuation; the eval pushes the continuation and the handler, then descends into the body (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:611-614`).
3. **Dispatch.** The eval pushes the suspension's own continuation, scans down the stack for the innermost handler whose tag matches, and errors out if none exists (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:531-536`).
4. **Answering.** The handler subclass decides the protocol. The general path folds the entries above the handler into the continuation with `dump(pos)` and calls the clause; the fast path fires only when the handler is at position 0, or under exactly one non-region `Step` (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:585-590`).
5. **Delivery.** When the current value is settled, the eval pops the receiving entry and applies it, with three special cases before the generic arrow application (stateful handler, plain handler, binding-extent end) (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:710-716`).
6. **Exit.** The eval always drains outstanding finalizers before pooling the stack and restoring the caller's safepoint state, in nested `finally` blocks so a throwing release cannot skip either (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:777-780`).

`Mask` is the proof that this region API is complete: it adds a new control-flow capability (selective effect masking) with no kernel support at all, as two `handleCont` calls (`kyo-kernel/shared/src/main/scala/kyo/Mask.scala:28-36`). `Kyo.scala` is the same point at the other end: 2694 lines of `foreach` / `filter` / `foldLeft` / `zip` / `collect` built purely on the `map` bind, with no node or `Eval` API in sight (`kyo-kernel/shared/src/main/scala/kyo/Kyo.scala:60-61`).

## The headline invariant: nest once, carry opaque, unnest once

### What the union is, and what it buys

`opaque type <[+A, -S] = A | Kyo[A, S] | Nested[A]` (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:45`). A settled value, a suspended node, and a `Nested` box for a value that is itself union-shaped are all the same static type, and they are told apart only by runtime class. Every public signature in every downstream module is written in this type.

`Nested` exists for one job: to disambiguate the union's first two arms. `nest` and `unnest` are the two operations that enter and leave the box (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:5,27-35`). Nothing else in the module is allowed to invent a fourth arm or a second boxing scheme.

### The three mechanisms, each tied to one operation kind

**Nest, at the lift boundary.** Entering the union boxes only a value that would itself read as a computation; everything else crosses unwrapped:

```scala
def nest[A, S](v: A): A < S =
    v match
        case v: (Kyo[?, ?] | Nested[?]) => Nested(v).asInstanceOf[A < S]
        case _                          => v.asInstanceOf[A < S]
```

(`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:32-35`). The public entry to that is the implicit lift, which resolves the primitive and `String` cases at compile time to a pure cast and only otherwise pays the runtime nest test (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Implicits.scala:10-15`). Nesting is one level per lift and is applied again to an already-boxed value rather than being idempotent (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/NestedTest.scala:44-51`).

**Carry opaque, in the evaluator.** The evaluator is one flat `@tailrec` loop whose currency is `Any < Nothing`, dispatching on the node's class; everything the kernel returns into it must be that currency (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:502-504`). A node's payload is a value already in hand, never a body to run: a deferred computation defers because its arrows have not been applied, not because reading the node runs anything, which is what lets an inspection walk through a deferral to the operation behind it without evaluating a step (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:23-26`).

**Unnest, at every strict delivery.** `Nested.unnest` strips exactly one level and is only legal at a site that has already excluded the pending arm (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:17-30`), pinned by test so a consumer that unnests twice or not at all is caught (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/NestedTest.scala:70-75`). Every strict path in the kernel calls `unnest` before handing a payload to user code.

`Nested.unnest` takes `Any`, not `A`, on purpose: typed `A`, the implicit lift would be in scope at every call site, and lifting a value that is already union-represented corrupts it (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:24-26`).

### The discrimination shape every consumer repeats

Every consumer of the union discriminates in the same order and the same shape: test the `Kyo` arm first and reify through `Effect.defer`, otherwise take the safepoint budget and, if it is granted, unnest exactly once and apply strictly:

```scala
v match
    case kyo: Kyo[A, S3] @unchecked =>
        Effect.defer(kyo, arrow, cont)
    case _ =>
        val slot = Safepoint.get()
        if !Safepoint.enter(slot) then
            Effect.defer(v, arrow, cont)
        else
            val out = cont.head(f(Nested.unnest(v)), cont.tail)
```

(`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:99-107`). The same three-arm discrimination is written out at every site that mints a standalone arrow, in the same order (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:44-51`). `Render` for the pending type shows the canonical arm order for inspection: pending node, box, raw value (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:491-495`).

`Effect.defer(v, cont)` is the reification of an application that could not run strictly, and it is defined to be observationally exactly `cont(v)` (`kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:81-88`). The budget arm is not an optimization: application on a settled value runs strictly until the safepoint budget drains, at which point it reifies instead of recursing (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:151-158`), and construction past the budget completing rather than overflowing is pinned as a behavioral guarantee (`kyo-kernel/shared/src/test/scala/kyo/kernel/PendingTest.scala:391-396`).

### Where the union rejects you, and where it must not be bypassed

- **A doubly-pending type is a compile error, not a silent lift.** `CanLift` rejects `A < S1 < S2` with a teaching message; the fix is `.flatten` or splitting the expression, never a cast (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/CanLift.scala:19-20`). The guard is real, so an ordinary `map` result cannot be silently re-nested, and the rejection is asserted as a compile failure (`kyo-kernel/shared/src/test/scala/kyo/kernel/PendingTest.scala:371-373`).
- **Kernel-internal code must not summon the lift.** It casts a raw value into the union directly: a raw value is already the union's first arm, and `Unit` admits no `Boxed` subtype, so there is nothing to nest. Lifting there would summon the macro inside a core kernel file, which is the cascade that ends in a stale-symbol crash on the clean build (`kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:39-45`).
- **A cast that stands in for the lift must say why the value cannot be `Boxed`.** That statement is the only thing making the cast equivalent to the lift (`kyo-kernel/shared/src/main/scala/kyo/kernel/Loop.scala:137-140`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Loop.scala:223-225`).
- **Substituting a cast for `Kyo.lift` where the payload can itself be a computation is a defect.** Only the lift's nest keeps the evaluator from mistaking data for a suspension; the bare cast fails a named pinning test (`kyo-kernel/shared/src/main/scala/kyo/kernel/Loop.scala:242-245`, `kyo-kernel/shared/src/test/scala/kyo/kernel/LoopTest.scala:770`).
- **The one deliberate re-nesting point in the public surface is `Isolate.nest`**, which uses `Kyo.lift` at a generic position precisely so the lift's runtime analysis nests the payload exactly once; a concrete `A < Restore` argument cannot take the conversion, since the lift's guard rejects syntactically pending types (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:152-157`).

### The same discipline, one layer up

- `Loop.Outcome` is the union discipline applied to clause results: `opaque type Outcome[A, +O] = O | Continue[A]`, a bare final value or a `Continue`, told apart by class (`kyo-kernel/shared/src/main/scala/kyo/kernel/Loop.scala:83`).
- A handler clause's answer crosses back to the evaluator as untyped currency plus an out-cell: the value is the return, the state and the branch travel in `Out`, and only the eval's dispatch tells the three apart (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:478-480`).

### What a new method over the union must do

1. Discriminate in the canonical order: `case kyo: Kyo[A, S] @unchecked => Effect.defer(...)` first, spelled identically to every other strict/deferring fork in the module (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:43-45`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:15-17`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Finalizer.scala:52-53`).
2. Read the settled arm through `Nested.unnest`, never with a bare cast at the use site; the helper states the precondition that makes it sound (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:20-30`), and it sits in the same position in the map expansion and in the region combinators (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:74`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:118`).
3. Take the budget before applying strictly, and fall into `Effect.defer` when it is denied (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:99-107`).
4. Bind an inline receiver to a local exactly once: `self` is inline, so every occurrence re-expands the receiver expression, and two occurrences would build the computation twice and run the function twice on the settled path (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:416-417`).
5. Return the eval's currency. Everything handed back into the loop is `Any < Nothing`-shaped (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:502-504`).

## Evaluation laws

These are the rules a new effect, handler or combinator has to respect. They follow from the representation above.

**Unhandled is a bug, not a state.** An operation reaching the evaluator with no handler anywhere fails: the row rules it out for both entry points, since a slice takes `A < Any` as well, and the exception is constructed rather than thrown so the effect trace attaches before the one throw (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:139-141`).

**A nested eval sees none of the enclosing regions.** An `Eval` called from inside a running computation borrows a fresh stack, so any effect still in the inner row becomes "Unexpected pending effect" at runtime (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:863-868`).

**Handler lookup is subsumption, binding lookup is equality.** A suspension is answered by the innermost enclosing handler whose tag is a supertype, the scan stopping at the first match (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:230-233`), while a binding is found by tag equality (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:222-224`). The two scans are deliberately not the same relation, and [Tag choice](#recipe-tag-choice-and-when-to-erase-it) is where that difference becomes a design decision.

**Regions must stay findable.** A region entry works by being present among the stack entries, so it must never be folded into an arrow; the type system enforces this by keeping `Region` out of `Step` (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:103-106`). Folding a handler, binding or finalizer into an arrow silently breaks the scans that find it: `Stack.find` for a handler, `lookup` and `resolve` for a binding, the drain for a finalizer (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:87-90`). `Stack.dump` is where the split earns its keep: a run of steps folds into an `AndThen`, and reaching a region ends the normalized run so the region lands back as its own entry (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:242-246`). Outstanding releases are held in their own array rather than as entries for exactly the same reason: a folded finalizer would be invisible to the drain (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:23-25`). `Cont` (`AndThen` | `Id`) is the normalized continuation shape the stack stores whole; `Chain` is the deliberately unnormalized shape a computation accumulates in while it is being built, so accumulating stays O(1) per combinator (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:151-156`).

**Continuations are complete values.** `ArrowEffect` supports multi-shot continuations: a clause may invoke the continuation many times or not at all (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:31-33`). Every shot replays the trailing maps folded into it, once per shot, at any depth (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:818-827`), and a continuation stays valid after the eval that produced it has completed, each shot resuming from capture-time state (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:759-775`).

**A settled body installs no region.** The combinator short-circuits to the `done` clause applied strictly to the unnested value, so a clause with observable behavior never runs (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:153-175`), pinned by test (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:173-176`).

**Bindings layer, they do not replace.** A binding holds a function of what is bound below it, resolved when the entry is installed, so nested scopes of one effect layer (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:88-91`). Reads and bindings are the same node kind, which is what carries that semantics into `ContextEffect` (`kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:24-25`). Because resolution happens at install time, a continuation captured inside a binding and resumed under a different enclosing binding merges into that one, not the one it was captured under (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:108-111`). `Kyo.Bindings` is the one node kind that reaches the whole stack rather than one entry: it writes updates into the scopes that own them and reads back what stands, in a single visit (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:629-636`).

**A release runs exactly once.** The run is CAS-guarded and the flag is set before the release runs, so a throwing release still counts as run (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Finalizer.scala:41-42`). It is atomic rather than a plain `var` because a captured continuation can be resumed on one thread while the eval that created it drains on another, so the two paths genuinely race (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Finalizer.scala:22-23`). `Finalizer` is one object filling three roles: the entry a stack holds, the arrow spliced after the extent it belongs to, and the flag that makes those two paths exclusive (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Finalizer.scala:15-27`). Re-entering a scope whose release already ran is refused at the entry with `Finalizer.Spent`, before the code inside the scope can read what is gone (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:43-53`). A completing region drains the releases owed above its own watermark, because a clause that completed without resuming its continuation orphaned those extents (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:184-190`).

**Failure unwinds on one walk.** A failure unwinds the entry stack to the innermost `Recover`, running every release it passes on the same walk, so a bracket opened inside a guarded scope releases before the recovery runs (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:464-471`). A clause's own failure escapes its region rather than being answered inside it: the interior entries release and their recoveries are passed over, and a release that throws is suppressed onto the failure rather than replacing it (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:508-511`). Recovery is driven by an outer `while` loop rather than a `try` inside `loop` or a recursive call, because a tail call may not sit inside a `try` and a recursive retry would cost a JVM frame per recovery (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:740-744`).

**A park is a whole eval state snapshotted as a value.** `Kyo.Park` holds entries, states, marks and outstanding finalizers as immutable `Span`s, so a parked computation is resumable more than once and on any thread (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:61-67`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:49-51`). A slice may not park in front of a binding, nor in front of the step that builds one, or a resource would exist that no drain can find: the eval carries it one step further into the scope that owes it (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:485-489`), implemented by walking to the payload's first receiver and rejecting a `BindingStep` (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:490-500`). A park carries its outstanding releases rather than running them, which leaves the holder with the choice; the holder that gives up calls `finalizeResources` (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:784-792`, `kyo-core/shared/src/main/scala/kyo/scheduler/IOTask.scala:473`). The isolate path reuses the same node: attaching crossed bindings builds a `Park` around the body, so one representation serves both crossing and parking (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:571-573`).

**The generated answer protocol.** The answer templates live in `Handler` because the protocol is the eval's, but each region call site expands its own copy with the clause statically bound, so the outcome box is born and dies inside one compiled method (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:106-112`); the wiring side overrides the generic `answer` / `answers` bodies with the template instantiated at that site (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:288-291`). State and branch cross back through one reused out-cell per stack rather than as a returned tuple, because that tuple was a measured allocation of exactly one object per answer (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:32-43`). The cell's `kind` lane is a four-value protocol read only by the eval's dispatch: answered, clause-suspended, clause-finished, clause-threw (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:398-405`).

**Two cost contracts that read as style but are not.** The order of the arms in the eval's match is a performance contract: `Park`, `Catching` and `Bindings`/`Binding` come last so common computations never pay a failed type test for them (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:615-617`). And `Eval.apply` is deliberately neither `inline` nor `@static`: the eval is around 555 instructions and HotSpot refuses to inline it anywhere, so an inline definition emitted a private copy of the whole interpreter per call site (132 of them in `PendingTest` alone), while Scala.js cannot emit a static method containing a lambda (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:90-96`).

**The two seams cost nothing when unused.** `Debugger` is a class-hierarchy-analysis seam, not a flag: real subclasses live in the debug tooling modules, so a production classpath never loads one and the identity defaults devirtualize to nothing (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Debugger.scala:7-13`); the eval reads it exactly once per evaluation so a session boundary never tears mid-eval (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:461-464`). `EffectTrace` records nothing while a computation runs: the frames are reconstructed at the boundary an exception crosses, from the failing node and the eval stack already in hand (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:14-19`). `EffectTrace.MaxFrames`, default 64, is one total cap across every boundary an exception crosses, innermost first, on the effect-level frames attached to a failure (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:42-45`). Adding a new internal class in the interpreter path means adding it to `EffectTrace.isPlumbing`, the list that keeps kernel internals out of user-visible stack traces (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:125-136`).

## Conventions

### Cast discipline

- Read the settled arm through `Nested.unnest`, not a bare cast, at every strict arm across the module (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:20-30`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:74`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:118`).
- A cast the array-backed stack forces is justified once, at the top of the walk that performs it, naming erasure as the cause (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:248-250`). The same "erasure-forced" phrasing is the module idiom wherever a `Span` or slot erases a value type (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:433-435`).
- A cast that stands in for the implicit lift states why the value cannot be `Boxed` or `Nested` (`kyo-kernel/shared/src/main/scala/kyo/kernel/Loop.scala:137-140`).
- A cast that widens or asserts an existential instantiation says which liberty it is taking (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:364-367`).
- Where a new hook would otherwise force the evaluator to cast, make the hook generic and push the burden onto the implementor (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Debugger.scala:47-49`).

### Inline usage

The root guide's default is that handling paths are not `inline`. This module inverts that for the region and handling combinators, because the clause has to be statically bound into the per-call-site answer method, which is the mechanism the design exists for (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:106-112`, contrast root CONTRIBUTING.md:838). The rest of the inline rules here:

- Anything the evaluator calls at runtime is deliberately not inline, and the refusal carries its measurement (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:89-91`).
- The cold arm an inline expansion falls into is a plain public method, so the site pays a call rather than a class (`kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:79-83`).
- Each region combinator marks its `answer` / `answers` override with a one-line comment pointing at the template it expands (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:163-172`).
- Every inline def whose body allocates an anonymous class carries `@nowarn("msg=anonymous")`; 31 of the 33 `@nowarn` annotations in the module's main sources are this exact one (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:63-64`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:144-145`).
- Symbols named inside an inline body are imported unqualified rather than selected from a companion, because a qualified selection does not resolve at an expansion site outside package `kyo`; the import block carries the reason (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:4-8`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:4-7`).
- An inline receiver or inline parameter read more than once is bound to a local exactly once (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:416-419`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:158`).
- A clause or by-name parameter used inside the anonymous class an expansion builds is first wrapped in a local `on<Clause>` def, because the class member of the same name would shadow the parameter (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:584-585`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:168-171`).
- The `Frame` given is named `_frame` whenever the expansion's anonymous class defines a `frame` member, and plain `frame` when it does not (`kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:65-68`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:47`).
- An inline template body loops with a `running` flag rather than an early return, because an inline body cannot `return` (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:111-112`).
- The region combinators take the body's row and a free row as a pair (`S`, `S2`), and the reason is recorded once above the family rather than on each member (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:121-126`).

An inline body that selects a `private[kyo]` name qualified, or names a `private[kyo]` top-level object, breaks only outside package `kyo`, which no in-package test can see; two such failures already shipped (`kyo-kernel/shared/src/test/scala/outsidekyo/KernelTest.scala:12-15`). That is why every new public inline entry point goes into the outside-`kyo` suite (`kyo-kernel/shared/src/test/scala/outsidekyo/KernelTest.scala:17-21`).

### Visibility, `@static`, and the inline-expansion boundary

What an inline body names has to be public, at both the object and the member level. A `private[kyo]` top-level object makes dotty emit an accessor whose receiver is the package itself, which the backend loads as `getstatic kyo/kernel/internal.MODULE$` and no such class exists; a `private[kyo]` member gets a well formed accessor instead, but the accessor is a second call the expansion pays for, measured at 5 bytes versus 20 for the value lift (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:12-17`). The whole module's visibility layout follows from that one constraint:

- The shape is "public object, `private[kyo]` members", repeated verbatim on every internal object an expansion reaches, each pointing back at the `Safepoint` note (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:29`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:20`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Debugger.scala:61`).
- Publicness forced by inline reach is paid back by withholding operations: the exposed types are opaque, or the class behind a public object stays private (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:16-17`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:7-9`).
- An opaque type gets only the bound a caller genuinely needs, and the doc states which bound was withheld and what that preserves, duplicated on both platform variants (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:20-23`, `kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/Safepoint.scala:28-31`).
- Where a class is exposed because an inline body forces it, the mutable state is narrowed instead and the doc says no inline method touches it (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:36-39`).
- Visibility narrows to the smallest qualifier that compiles, including type-scoped qualifiers such as `private[Arrow]`, not just `private[kyo]` (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:228`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:637`, `kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:69`). This refines the root guide's Visibility Tiers table, which lists only public, `private[kyo]` and `private`.
- Cross-platform members keep matching visibility even where a platform would allow narrower, because shared inline expansions name them (`kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/Safepoint.scala:22-24`).

`@static` is the default for the boundary primitives on jvm-native, with the js-wasm mirror using a plain module member and a paired comment saying why (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/StackPlatformSpecific.scala:9-11`, `kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/StackPlatformSpecific.scala:7-9`). Two exceptions are load-bearing: `@static` on a symbol named from an inline-expanded body crashes a downstream macro-owning module's clean build, so `Nested`'s members are plain module methods (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:11-14`), and `@static` on a method containing a lambda does not compile on Scala.js, which is why the evaluator's entry point is the one boundary primitive without it (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:93-96`). An object carrying `@static` members is paired with an otherwise-empty companion class at the same visibility (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:10`, `kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/DebuggerPlatformSpecific.scala:5`).

### Comments in internal files

- Every internal class opens with a scaladoc that says what the thing is and why it has that shape, not what its methods do (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Finalizer.scala:15-27`, `kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:103-111`).
- The justification idiom is "X rather than Y: reason", used 88 times across the module's main sources; it names the rejected alternative in the same sentence as the choice (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Finalizer.scala:22-23`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:11`).
- A performance claim carries its measurement, in the unit it was measured in (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:10-13`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:411-414`).
- A shape that was tried and rejected is recorded as rejected, with who rejected it, so it is not re-proposed (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:148-150`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Debugger.scala:29-30`).
- The ordering of `match` arms is treated as a decision and commented where it is load-bearing (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:615-617`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:310-312`).
- Duplicated index arithmetic is kept duplicated on purpose and says so, so a reader does not clean it up and split the three copies apart (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:164-167`).

### Naming

- The evaluator's erased operation types are abstract type members with an `X` suffix (`IX`, `OX`, `EX`, `CX`, `AX`, `BX`, `StateX`, `SX`), and any other file needing the same erasure re-declares the same names privately (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:80-88`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:49-52`).
- A `*With` variant means "the caller's continuation is fused into the node this builds", both for operations and for regions (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:374-377`).
- Singular `answer` answers one operation; plural `answers` is the per-site loop that keeps answering. The pair recurs on all three handler kinds (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:485-503`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:430-445`).
- Node classes are `abstract private[kyo] class` so each construction site implements the members anonymously and keeps its own types, which is what stores a primitive input unboxed; a concrete node is the exception and says why (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:328-331`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:57-61`).
- A member that would collide with a JDK member is renamed and the rename is recorded inline, for instance `release` rather than `finalize` (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:148-154`).

### Frames

An arrow the kernel mints with no user site reports `Frame.internal`, and the trace builder skips exactly that value (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:164`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:195-196`). When the kernel composes a `map` on the user's behalf it passes the operation's own frame explicitly rather than summoning one at the site (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:188-190`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:132-134`).

### Errors

A state the kernel's own invariants rule out raises `bug` or `bug.exception`, never an ad-hoc exception (`kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:71`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:653`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:504`). A module exception lives in the companion of the thing it describes, and its doc justifies both object-versus-class and `NoStackTrace`-versus-not (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Finalizer.scala:71-83`).

### The concession pattern

A deliberate departure from the module's own rules is written as a four-part concession, derived from `Handler.Out`, the mutable out-parameter cell: (1) the justification with a measurement, (2) the smallest scope it is confined to, (3) what makes it unreachable from user code, (4) a statement that it is never the only copy of anything (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:32-42`). The same shape recurs for the pooled mutable `Stack` (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:28-31`). The concession is then pinned in tests by a section that names it as a concession and declares its cases hostile axes rather than construction arguments (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1629-1633`).

Decisions with a measurable compiled footprint get a bytecode pinning test whose doc says the number is a result to look at, never a baseline to rewrite (`kyo-kernel/jvm/src/test/scala/kyo/kernel/ArrowEffectBytecodeTest.scala:7-10`, `kyo-kernel/jvm/src/test/scala/kyo/kernel/PendingBytecodeTest.scala:8-11`). A decision not to have something is pinned with a negative compile test stating what returns if the decision is reversed (`kyo-kernel/shared/src/test/scala/kyo/ArrowTest.scala:150-156`), and such a pin asserts the compiler's actual message, never merely that compilation failed (`kyo-kernel/shared/src/test/scala/kyo/Test.scala:19-27`).

## Extension recipes

### The two extension points, and the ceiling above them

`Effect`'s constructor is `private[kernel]`, so `ArrowEffect` and `ContextEffect` are the only effect kinds a contributor can define; a new effect subclasses one of those two, never `Effect` (`kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:31`). The internal layer is sealed to match: the node graph is sealed and `private[kyo]`, so a new capability is composed from the existing nodes and can never be a new node kind (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:18`); the handler hierarchy is sealed, so `HandlerCont`, `HandlerLoop` and `HandlerLoopState` are the only handler kinds (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:12`); and `Arrow` is a sealed trait whose implementation traits are `private[kyo]`, so `Arrow.apply` and `Arrow.recursive` are the only ways to build one (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:14`).

Some of the surface is `private[kyo]` and stays that way: `handleFirst` (answer one operation, hand back the raw remainder) and `dispatchFirst` (inspect the standing operation without evaluating) exist for the stream pipes and the scheduler (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:348`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:556`); `handleCatching` is handling fused with a recovery scope, with `Effect.catching` as the public recovery surface (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:575`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:99-103`); `Isolate.internal.Contextual` is `private[kernel]` and reached only through a derived instance (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:539-541`). `Safepoint`, `Nested`, `Eval` and their kin are public objects with `private[kyo]` members for exactly one reason, that inline expansions in downstream modules name them, and that is not an invitation to use them (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:7-9`).

### Recipe: add a new ArrowEffect

1. Declare `sealed trait E[...] extends ArrowEffect[Input, Output]` at the top of its own file. `Var[V] extends ArrowEffect[Const[Op[V]], Const[V]]` and `Emit[-V] extends ArrowEffect[Const[V], Const[Unit]]` are the two worked examples (`kyo-prelude/shared/src/main/scala/kyo/Var.scala:40`, `kyo-prelude/shared/src/main/scala/kyo/Emit.scala:34`).
2. Add operation methods in the companion calling `ArrowEffect.suspend` or `suspendWith` with `Tag[E]`. Each is `inline`, takes `Tag[E]` before `Frame` in the `using` clause, and delegates straight through with no logic of its own (`kyo-prelude/shared/src/main/scala/kyo/Var.scala:81-82`, `kyo-prelude/shared/src/main/scala/kyo/Var.scala:108-109`).
3. Add `run*` handlers calling one of the `handle*` variants (see the discriminator below).
4. Optionally add an `isolate` object or a `given isolate`.

`suspend[C]` takes the operation's type argument explicitly as its first parameter list, then `(effectTag, effectInput)`, and produces `O[C] < E`; the leading `[C]` is what carries a non-`Const` operation's element type (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:76-81`).

| Situation | Use | Example |
|-----------|-----|---------|
| Both `Input` and `Output` are `Const`, so nothing depends on `C` | `suspend[Any]` | `Emit` (`kyo-prelude/shared/src/main/scala/kyo/Emit.scala:47`) |
| `Input` or `Output` is a genuine type constructor | `suspend[A]` with the real element type | `Choice`, whose row is `Seq => Id` (`kyo-prelude/shared/src/main/scala/kyo/Choice.scala:55`) |
| The answer is consumed immediately by a known function | `suspendWith`, which fuses the suspension and its continuation into one step so the call site stays one allocation | `Var.use`, `Abort.error` (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:88-89`, `kyo-prelude/shared/src/main/scala/kyo/Var.scala:70`, `kyo-prelude/shared/src/main/scala/kyo/Abort.scala:71`) |

### Recipe: choose and write the handler

The handling variant is chosen by what the clause needs (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:49-53`):

| The clause needs | Variant | Returns to the eval | Worked example |
|------------------|---------|---------------------|----------------|
| The continuation in hand, to apply many times or not at all (backtracking, early return) | `handleCont` | the region's answer built from the continuation value | `Check.runAbort`, which never resumes (`kyo-prelude/shared/src/main/scala/kyo/Check.scala:76-79`) |
| To answer each occurrence, no state between them | `handleLoop` | a `Loop.Outcome` | the loop family (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:49-53`) |
| To thread state between occurrences | `handleLoopState` | a `Loop.Outcome` plus the new state through the out-cell | `Var.runWith`, where the state is the variable (`kyo-prelude/shared/src/main/scala/kyo/Var.scala:144-147`) |
| The region's result consumed by a known continuation | the `*With` form (`handleContWith`, `handleLoopWith`, `handleLoopStateWith`) | the continuation fused into the region node instead of mapped over it | `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:374-377` |
| To complete with the body's own value | the form without a `done` clause, which delegates to the form with one | `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:178`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:316` |

Every region combinator carries the row as a pair, `S` for the body's row and `S2` as a free variable for whatever the clause adds. With a single row the typer commits it to the body's row before the clause is seen, so a clause that introduces its own effect (`Abort` in `Check.runAbort`, the fold function's row in `Emit.runFold`) cannot widen it and the site needs explicit instantiation. A new region combinator keeps the pair (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:121-126`).

To add a new `handle*` variant to `ArrowEffect`, build a `Kyo.Handle` whose `handler` is an anonymous `HandlerCont` / `HandlerLoop` / `HandlerLoopState`, and override `answers` (plus `answer` for the loop kinds) with the matching template from `Handler` so the clause is statically bound: `handleCont` overrides with `answersCont`, `handleLoop` with `answerStep` plus `answersLoop` (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:163-172`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:224-235`).

Two traps here:

- **Omitting the `answers` override still compiles and is still correct**, because the base implementation runs the clause through a virtual call, so the loss is silent: consecutive same-tag answers stop looping inside one compiled method. `handleCatching` is the one variant in the file that does not override it (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:411-413`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:592-597`).
- **A `Loop` clause written under a region must ascribe its resumed value at the region's row** (`Loop.continue(1: Int < Any)`), because the clause answers at the region's row and not at the successor's (`kyo-kernel/shared/src/test/scala/outsidekyo/KernelTest.scala:23-25`, `kyo-kernel/shared/src/test/scala/kyo/kernel/IsolateTest.scala:34-35`).

### Recipe: tag choice, and when to erase it

Handler dispatch finds a region by tag subsumption, so a handler for `E` answers operations suspended at any subtype of `E`; that is how one effect at many type arguments becomes separate handlers (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:232`, `kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:23-24`). A context read finds its binding by tag equality, so two `ContextEffect` instantiations at different type arguments are different names unless their tags are made identical (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:223`).

- When an effect's type parameter must not gate matching, add a private `erasedTag[X]: Tag[E[X]] = Tag[E[Any]].asInstanceOf[Tag[E[X]]]` and use it at every suspend and handle site. `Abort` does this so any `Abort` region catches any `Abort` operation; `Env` does it so all `Env[R]` bindings share one name and layer through `_.union(env)` (`kyo-prelude/shared/src/main/scala/kyo/Abort.scala:48`, `kyo-prelude/shared/src/main/scala/kyo/Env.scala:152`).
- For many independently-scoped values under one effect, share one tag and make the bound value a map each binding updates rather than replaces: `Local.let` binds `_.updated(this, value)` over `Tag[State]`, which is exactly what the `Binding` node's function-shaped `bound` exists for (`kyo-prelude/shared/src/main/scala/kyo/Local.scala:76-83`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:105-106`).

### Recipe: add a new ContextEffect

1. `sealed trait E extends ContextEffect[A]`.
2. Reader methods calling `ContextEffect.suspend` or `suspendWith` with the tag.
3. A `run`-style method calling `ContextEffect.handle(tag, ifUndefined, ifDefined)(v)`.
4. `fork` / `join` / `release` arguments only where the defaults are wrong.

`Env` (erased tag, `_.union(env)` as `ifDefined`) and `Scope` (`Tag[Scope]`, `_ => finalizer` as `ifDefined`) are the two worked examples (`kyo-prelude/shared/src/main/scala/kyo/Env.scala:98`, `kyo-core/shared/src/main/scala/kyo/Scope.scala:132`).

`ContextEffect.handle`'s three edge parameters are the whole binding-lifecycle extension surface, each defaulting to the plainest answer: `fork` is what a forked computation receives, `join` is what the binding holds once a fork ends, and keeping this one, taking the fork's, or merging them is the whole of an isolate strategy; `release` is what the value owes when the extent ends (`kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:142-146`). `release` is a `Maybe` of a function taking the held value and the extent's `Result`, not a plain function with an empty default, so a binding that owes nothing pays nothing; the call shape is `release = Maybe((v, result) => ...)` (`kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:145-146`, `kyo-kernel/shared/src/test/scala/kyo/kernel/ContextEffectTest.scala:173`).

Reach for the two-argument `ContextEffect.suspend(tag, default)` overload when the value should be optional: it returns `A < Any`, so a reader with a default names no effect at all. `Local.get` and `Local.use` both use the `suspendWith` form of it (`kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:84-88`, `kyo-prelude/shared/src/main/scala/kyo/Local.scala:55`).

**There is no non-inheritable marker type or annotation to reach for.** A binding that must not cross a fork says so with `fork = _ => Absent`, which is also how a binding crosses as something else, where a type could only say yes or no; the kernel documents the absence of a marker as the deliberate choice (`kyo-kernel/shared/src/main/scala/kyo/kernel/ContextEffect.scala:35-36`). `Local.initNoninheritable` is exactly that spelling (`kyo-prelude/shared/src/main/scala/kyo/Local.scala:160-161`). The root guide's API Design > Types section still says to "mark with `ContextEffect.Noninheritable`"; no such symbol exists anywhere in kyo-kernel's source, so that line is stale and this section is the ground truth.

### Recipe: add an Isolate

An isolate for a new effect implements two type members and three phases: `type State`, `type Transform[A]`, `capture` (read the state where the fork happens), `isolate` (run the body handled, producing `Transform[A]`), `restore` (write it back). `Var.isolate.Base` and `Emit.isolate.merge` are the two worked examples, and for one effect only `restore` differs between strategies (`kyo-prelude/shared/src/main/scala/kyo/Var.scala:199-208`, `kyo-prelude/shared/src/main/scala/kyo/Emit.scala:223-234`).

- An effect with one obvious policy exposes it as `given isolate: Isolate[E, Any, E]` in its companion so derivation picks it up without a `use` block; `Check` writes the instance inline, `Memo` delegates to `Var.isolate.merge` (`kyo-prelude/shared/src/main/scala/kyo/Check.scala:114`, `kyo-prelude/shared/src/main/scala/kyo/Memo.scala:68`).
- **Do not provide an isolate for a short-circuiting effect.** Derivation composes instances in the order the effects appear, so the result would depend on which one is handled first (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:79-80`).
- A `ContextEffect` needs no isolate instance of its own: `Isolate.derive` drops every `ContextEffect` from the `Remove` row before summoning, because context bindings cross through `Contextual`, which every derived instance folds from (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:601-609`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:656-658`). Materialization flattens the `Remove` intersection, drops `Keep` and `ContextEffect` members, summons an instance per remaining effect, and folds them onto `Contextual` with `andThen` (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:656-658`).
- A missing isolate is a compile error carrying a four-option teaching message (handle the effect first, use the effect's `isolate` object, compose with `andThen`, or write a custom instance); that message is the contract a new effect's isolate story is judged against (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:613-653`).
- `Isolate.andThen` drops no side, not even the neutral `Contextual`, because `Contextual` manages the scope the effects are read in; a new composition helper must preserve it (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:249-251`).
- `Isolate.run(state, v)` is deliberately overridable: the `restore(isolate(...))` body is the meaning, not the required implementation, so an instance that can cross without building a `Transform` says so once and every caller benefits (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:180-182`).
- `Isolate.nest` returns `A < Restore < (...)` and works only because it goes through `Kyo.lift` at a generic position; a direct ascription to `A < Restore` is rejected by the lift discipline, so copy the shape rather than simplifying it (`kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:152-157`).

### Recipe: mask an effect between two points

`Mask[S]` is itself an `ArrowEffect` whose input is a whole pending computation (`sealed abstract class Mask[S] extends ArrowEffect[[A] =>> A < S, Id]`), so a masked operation travels to `Mask.run` as an unevaluated payload and is re-raised there (`kyo-kernel/shared/src/main/scala/kyo/Mask.scala:12`, `kyo-kernel/shared/src/main/scala/kyo/Mask.scala:28-30`).

1. Wrap with `Mask[E](v)`, naming the effect explicitly; the type argument is not inferred (`kyo-kernel/shared/src/main/scala/kyo/Mask.scala:18-19`).
2. Install the local handlers over the masked value.
3. Unmask with `Mask.run[E](...)` at the boundary where the outer handlers should see it (`kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:26-29`).

Masking is selective by construction: every other effect in the row stays visible to the local handlers, and the outer answer flows back into the masked computation (`kyo-kernel/shared/src/main/scala/kyo/Mask.scala:5-10`), pinned end to end (`kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:47-57`). `Mask` accepts only an `ArrowEffect`: the bound is `E2 >: E <: ArrowEffect[I, O]` and the call needs both `Tag[E2]` and `Tag[Mask[E2]]`, so there is no way to mask a `ContextEffect` with it (`kyo-kernel/shared/src/main/scala/kyo/Mask.scala:21-27`).

### Recipe: add to the kernel's own surface

- **A new public inline entry point** gets a case in `outsidekyo/KernelTest.scala` that both compiles and runs it: compiling proves the name resolves, running proves the accessor the compiler emitted for it is well formed (`kyo-kernel/shared/src/test/scala/outsidekyo/KernelTest.scala:11-15`, `kyo-kernel/shared/src/test/scala/outsidekyo/KernelTest.scala:20-21`). `Implicits.abortCastUnit` is the one deliberate omission, since it exists to fail compilation.
- **A new platform-specific member** is defined in both `jvm-native/.../internal` and `js-wasm/.../internal` with an identical member surface and identical visibility, differing only where the platform forces it. `StackPlatformSpecific` and `DebuggerPlatformSpecific` are the two worked pairs (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/StackPlatformSpecific.scala:9-10`, `kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/Safepoint.scala:22-24`).
- **A new internal class in the interpreter path** is added to `EffectTrace.isPlumbing`, or it shows up in user-visible stack traces (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:125-136`).
- **Diagnostics go through `Debugger`**, an abstract class with identity defaults and one installed instance via `install` / `uninstall` / `get`; real subclasses live in the debug tooling modules rather than in the kernel (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Debugger.scala:10-12`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Debugger.scala:73`).

### Traps a new effect hits

- **A multi-shot clause over a body holding a bracket is refused at the second branch with `Finalizer.Spent`**: the resource was released when the first branch completed, and re-entering its scope would read what is gone. `handleFirst` inherits the refusal, since its clause runs in `handleCont`'s done lane (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:43-53`, `kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:1211-1213`).
- **An effect whose `Output` is itself a pending computation** (`ArrowEffect[Const[Unit], [X] =>> Int < Say]`) cannot hold that computation through a direct ascription: the lift's guard rejects syntactically pending types, so holding a computation as data goes through a generic indirection such as `def box[A](v: A): A < Any = v` (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:28-35`).

## Cross-platform

Only three main-source files are platform-specific, and each has exactly two copies, one under `jvm-native/` and one under `js-wasm/`: `Safepoint.scala`, `StackPlatformSpecific.scala`, `DebuggerPlatformSpecific.scala`. Everything else in the module is in `shared/` (`kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/Safepoint.scala:8`).

| Concern | jvm-native | js-wasm |
|---------|-----------|---------|
| `Safepoint` | A global open-addressed slot table keyed by thread id, holding a depth-guard budget per slot and a stop sentinel for cross-thread preemption (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:43-54`) | Two module vars, because preemption is a slice deadline rather than a cross-thread sentinel: the depth-guard budget, the armed bit, and a deadline armed once at slice entry (`kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/Safepoint.scala:11-14,56-57`) |
| Static members | `@static` on the boundary primitives (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/StackPlatformSpecific.scala:9-11`) | A plain module val, because a Scala.js static field initializer runs at script evaluation in file order and can capture `undefined` for a dependency defined later (`kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/StackPlatformSpecific.scala:7-10`) |

The two `Safepoint` variants must expose an identical member surface, visibility included, because shared inline expansions (the value lift, `deferInline`, the eval loop) name those members from downstream modules (`kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/Safepoint.scala:22-25`).

The directory names are load-bearing for the build. `jvm-native/` and `js-wasm/` are the build's partially-shared directories, named by joining platform identifiers with a dash, and the build tooling maps a changed file under one of them to exactly those platforms' projects (`project/TestKyo.scala:403-412`). Stacks come from a per-thread pool, reached through `StackPlatformSpecific.local`, so an eval allocates no stack of its own in steady state (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:659-661`).

Per-platform test roots follow the same split: `jvm-native/src/test` holds the threading suites, `jvm/src/test` holds the bytecode-shape pins (which need javassist) and the safepoint-concurrency suite, and JVM test parallelism is off because the safepoint slot table is global (`build.sbt:786-788,806-809`). The JVM project is also the only one carrying benchmarks: `jvm/src/jmh` holds `KernelBench` plus cross-framework comparisons whose libraries are jmh-scoped so they never reach the compile or test classpaths (`build.sbt:798-805`).

## Testing

### The base, and why it is not kyo-test

Kernel suites extend a module-local `kyo.Test` built directly on ScalaTest `AnyFreeSpec` with `NonImplicitAssertions` (`kyo-kernel/shared/src/test/scala/kyo/Test.scala:17`). The reason is observer-outside-observed: the kernel sits under every other module including the test framework, so running these suites on kyo-test would put the scheduler's preemption inside the state they assert on (`kyo-kernel/shared/src/test/scala/kyo/Test.scala:10-15`). The build states the same rule: kyo-kernel takes a plain ScalaTest `Test` dependency and never calls `.withKyoTest` (`build.sbt:774-778`), while kyo-prelude, the first module above the kernel, does (`build.sbt:820`). `WithKyoTest`'s own scaladoc example still names `kyo-kernel` as a `.withKyoTest` user; copying it would undo the rule (`project/WithKyoTest.scala:28-31`).

Every suite extends that base, spelled `kyo.Test` from any package other than `kyo` and bare `Test` inside package `kyo` (`kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:17`, `kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:6`).

- `NonImplicitAssertions` is mixed in, so ScalaTest's implicit conversions are off: no `===`, no `shouldBe`, no matchers anywhere in the corpus. The vocabulary is `assert`, `intercept`, `succeed` (`kyo-kernel/shared/src/test/scala/kyo/Test.scala:17`, `kyo-kernel/shared/src/test/scala/kyo/kernel/IsolateTest.scala:84-85`).
- `Test.typeCheckFailure(code)(expected)` is the module's negative-compile assertion and fails unless the compiler's actual message contains the pinned substring (`kyo-kernel/shared/src/test/scala/kyo/Test.scala:19-27`). A rejection is always pinned to the real message text, never to "it did not compile" (`kyo-kernel/shared/src/test/scala/kyo/kernel/PendingTest.scala:376`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/ImplicitsTest.scala:94`). This is the same substring-match contract the root guide describes for kyo-test's helper; the module-specific part is that kyo-kernel keeps its own copy, for the same layering reason it does not run on kyo-test at all.
- ScalaTest's `assert` macro renders its argument's source into a string constant, so an inline `eval` expansion inside `assert(...)` blew the JVM's 64KB method limit; bind the result to a `val` first (`kyo-kernel/shared/src/test/scala/kyo/KyoTest.scala:43-47`).
- Opaque kernel types are compared with `.equals`, not `==`, and the site says why rather than adding a cast for the test's convenience (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:912-914`, `kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1992`).

Two conventions to follow that the corpus does not yet follow everywhere:

- **New negative-compile assertions use `Test.typeCheckFailure`** (`kyo-kernel/shared/src/test/scala/kyo/Test.scala:23`). `CanLiftTest` predates this and still carries its own private `rejects` helper doing the same substring check by hand (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/CanLiftTest.scala:12-17`).
- **A suite that needs the safepoint period reads it from `Safepoint.period()`** (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:14`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/StackTest.scala:20`), because 512 is only the default of an overridable `StaticFlag` (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:56`). Three suites still hardcode `512` (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:37`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointTest.scala:7`, `kyo-kernel/jvm/src/test/scala/kyo/kernel/internal/SafepointConcurrencyTest.scala:11`).

### Naming, placement, fixtures

- Test files are 1:1 with the source they cover, and a split carries a closed-vocabulary aspect suffix naming why it is separate: `Threading`, `Bytecode`, `Concurrency`, `Physical`, `UnstartedThread`, `CaptureTower` (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/ArrowEffectThreadingTest.scala:12`, `kyo-kernel/jvm/src/test/scala/kyo/kernel/ArrowEffectBytecodeTest.scala:11`).
- Every out-of-`shared` test file opens with a scaladoc header stating what forced it off the cross-platform path and naming the shared sibling that keeps the rest (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/ArrowEffectThreadingTest.scala:8-10`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/EffectThreadingTest.scala:8-9`), and the shared file carries the matching back-pointer so the corpus is navigable from either end (`kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:651-652`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EffectTraceTest.scala:347-348`).
- The bar for leaving `shared/` is that the case is not expressible or not portable, stated concretely, never that the platform infra is inconvenient (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointUnstartedThreadTest.scala:6-8`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/EffectTracePhysicalTest.scala:9-10`).
- A file kept separate purely for run and debug ergonomics says so in its header rather than being silently duplicated coverage (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalCaptureTowerTest.scala:9-10`).
- Per-suite fixtures are declared inline as a `sealed trait` effect plus a suspend helper plus an `answerAsk`-style handler, rather than pulled from a shared base class (`kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:19-23`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:16-31`). When two suites need the same fixture it goes into a companion object in the sibling test file, not into `Test` (`kyo-kernel/shared/src/test/scala/kyo/KyoForeachTest.scala:5`, `kyo-kernel/shared/src/test/scala/kyo/KyoForeachCollTest.scala:6`).
- Tests state observable semantics through the public surface; direct node construction, `Stack`, `Nested` and `Safepoint` internals appear only in the `kyo.kernel.internal` suites, where the internal unit is itself under test (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/StackTest.scala:27-28`).
- `@TestVariant` is inert in kyo-kernel: the annotation class is copied into the module's test sources but the sbt source generator is wired only on kyo-direct, so `KyoForeachCollTest` compiles and runs only the `Seq` base, never the `List` and `Chunk` variants the annotation names (`kyo-kernel/shared/src/test/scala/kyo/KyoForeachCollTest.scala:3`, `kyo-kernel/shared/src/test/scala/kyo/TestVariant.scala:5`, `build.sbt:1378` against the kyo-kernel settings block at `build.sbt:772-810`).

### Deterministic timing without a clock

The kernel sits below `Async`, `Channel` and `Fiber`, so the root guide's barrier primitives are unavailable here. The replacements:

- `internal.SafepointStop.request()` is the module's park driver: shared tests lodge a preemption stop from inside the computation and the per-platform implementation decides how it reaches the slot (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointStop.scala:7-9`, `kyo-kernel/js-wasm/src/test/scala/kyo/kernel/internal/SafepointStop.scala:5-8`). The two implementations differ only in how the request lands: a dispatched stop on jvm-native, a past deadline on js-wasm (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointStop.scala:13-14`, `kyo-kernel/js-wasm/src/test/scala/kyo/kernel/internal/SafepointStop.scala:12-13`).
- A park test asserts the three-part shape: the slice parked (`p.evalNow.isEmpty`), nothing was released or committed at the park, and the resumed eval yields the full value (`kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:687-691`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:947-949`).
- `drainedBudget` forces the budget-denied arm deterministically by draining the slot's budget under a save/restore pair, so the deferral path is exercised without running 512 steps (`kyo-kernel/shared/src/test/scala/kyo/kernel/PendingTest.scala:699-706`).
- Cross-thread coordination is a `@volatile` readiness flag spun on, then a bounded `join`, then an assertion that the thread actually ended; there is no `Thread.sleep` anywhere in the module's tests (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/EvalThreadingTest.scala:104-107`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/EffectThreadingTest.scala:29-32`). The JVM concurrency suite factors the wait into one deadline-bounded `spinUntil` helper (`kyo-kernel/jvm/src/test/scala/kyo/kernel/internal/SafepointConcurrencyTest.scala:15-18`), and the slot-table cases that need thousands of live threads use virtual threads plus `CountDownLatch` gates (`kyo-kernel/jvm/src/test/scala/kyo/kernel/internal/SafepointConcurrencyTest.scala:246-258`).
- Where the landing point of a stop is not exactly determined, the assertion is a tight bounded range with the reason stated, never a loose "it eventually parked" (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:2038-2039`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/EvalThreadingTest.scala:72-75`). A genuinely probabilistic delivery is made reliable by repetition, with the tolerance and the one legal escape spelled out in the comment (`kyo-kernel/jvm/src/test/scala/kyo/kernel/internal/SafepointConcurrencyTest.scala:109-141`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/EffectThreadingTest.scala:39-57`).
- `Eval.finalizeResources` is how abandonment is driven deterministically after a park, including in the abandon-versus-resume race (`kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:727-729`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/EffectThreadingTest.scala:50-51`).
- Unbounded stack growth is made observable by running the scenario on a thread with an explicit small stack (256 KB) rather than by inspecting frames (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/ArrowEffectThreadingTest.scala:70-85`). Stack-safety pins assert a concrete result at a named depth (1M through maps, 100k through a suspension, 10k through a mask), never merely "no exception" (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:87`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:99`, `kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:124`).
- Safepoint state is process-global (a per-thread slot in a shared table), so a suite must leave the slot as it found it, with an explicit save/restore or a `finally` exit pair (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1983-1995`, `kyo-kernel/shared/src/test/scala/kyo/kernel/PendingTest.scala:705`). JVM test parallelism is off for the whole module for the same reason: the overflow suite fills the global slot table and would degrade any concurrently running suite's threads (`build.sbt:806-809`). The `Debugger` suite has the same shape of problem and installs its process-global session in a `try` / `finally`, filters events to its own file's frames, and synchronizes its buffer (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/DebuggerTest.scala:22-24`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/DebuggerTest.scala:54-57`).

### Covering a concession, and covering a new construct

When a change concedes interpreter mutability, the corpus opens a section whose header names the concession and declares its cases hostile axes rather than construction arguments (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1629-1633`). The axes are the same four for every such concession, applied to both dispatch lanes: multi-shot replay of a capture, a full nested eval run inside a clause, a throw mid answer loop, and a park taken mid answer loop (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1635-1736`, `kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1739-1840`). A multi-shot pin replays the capture at least twice on the calling thread and names the jvm-native file that owns the cross-thread replay (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1653-1656`); the cross-thread half is a literal mirror of the shared case, same body, resumed on a `new Thread`, so the two files can be diffed against each other (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/ArrowEffectThreadingTest.scala:20`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/ArrowEffectThreadingTest.scala:38-43`). A throw-recovery axis asserts exactly which commits survived, by recording every clause run into a buffer and comparing the full list (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1716-1718`). A `"safety audit pins"` section holds the adversarial cross-lane cases, each comment stating the law it defends rather than the code path it walks (`kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1843`, `kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1890-1892`).

Cover a new cross-cutting construct the way `MaskTest` covers `Mask`: first the base semantics (one operation, every operation, an operation outside the construct, selectivity against a second effect), then an `"interactions" -` block crossing it with each kernel mechanism, then an independence case for two instances of the construct (`kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:25,32,39,47,59,140`). The interaction checklist is fixed: bracket release on the answered path, bracket release when the outer handler discards the continuation, `Effect.catching` across the construct, a stateful local handler threading state through it, a multi-shot outer handler replaying it, deep stack safety, and idempotence of double application (`kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:61-137`). Effect-order assertions are exact ordered lists built by prepending into a local `var` and reversing, or by appending into a `ListBuffer`, never bare counters (`kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:62`, `kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:73`), and a multi-shot interaction asserts both the composed result and the local effects each replay produced (`kyo-kernel/shared/src/test/scala/kyo/MaskTest.scala:120-121`).

Double-nesting (a computation held as data, boxed twice) is pinned in its own case at every layer that can see it: the representation, evaluation, and the budget-denied arm (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/NestedTest.scala:44`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:108`, `kyo-kernel/shared/src/test/scala/kyo/kernel/PendingTest.scala:720`).

### The safepoint contract pins

`SafepointTest` is where the stop channel's contract lives, and a change to preemption is judged against it: a delivered stop is consumed exactly once and a second `stop` while one is pending is idempotent rather than additive (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointTest.scala:9-22`); an addressed stop is honored only while its slice runs, with the stale sentinel taken out so the channel is clean for the next request (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointTest.scala:32-46`); a stop addressed to a departed slice must not short-circuit the next evaluation, pinned by running a 100-step chain to completion (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointTest.scala:68-83`); and the budget is pinned as an exact count, `enter` succeeding exactly `Period` times before denying, with `reset` and `restore` returning the slot to a usable state (`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointTest.scala:86-97`).

### Reproduction-first discipline in the corpus

- A regression test carries its provenance above the case: the symptom, why it was invisible, and the measured magnitude (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:890-895`).
- When the mechanism a test used to exploit is gone, the case is rewritten to reach the same semantics through the current surface and the comment records the swap, rather than being deleted (`kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:282-285`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EvalTest.scala:966-969`).
- A group of failures sharing one root cause is introduced by a block comment naming the cause with file:line into the implementation, so the tests read as one diagnosis rather than four unrelated cases (`kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:1319-1325`).
- A gap discovered but not previously covered is stated as such in the case that closes it (`kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:1410-1413`).
- An accepted limit is recorded in place with the cost of closing it, keeping the would-be assertion commented out, instead of being weakened into a passing test or dropped (`kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EffectTraceTest.scala:197-209`, `kyo-kernel/shared/src/test/scala/kyo/kernel/internal/EffectTraceTest.scala:248-249`).
- No probe or scratch test file ships: the module's three `jvm/src/test` files are all named after the source they pin (`kyo-kernel/jvm/src/test/scala/kyo/kernel/PendingBytecodeTest.scala:12`).
- A bytecode-size pin is an exact `Map` equality with a comment explaining the composition of the number (`kyo-kernel/jvm/src/test/scala/kyo/kernel/PendingBytecodeTest.scala:38`).
- The `suspend` / `suspendWith` / `handleCont` compiled size at a user call site is pinned by test at 14 / 14 / 40 bytes: what every user call site expands to, where a size that moves is a result to investigate, never a baseline to rewrite (`kyo-kernel/jvm/src/test/scala/kyo/kernel/ArrowEffectBytecodeTest.scala:9`, `kyo-kernel/jvm/src/test/scala/kyo/kernel/ArrowEffectBytecodeTest.scala:25-29`).

## Checklist: adding a new X to kyo-kernel

Run this before writing code.

1. **Is it an effect?** Then it subclasses `ArrowEffect` or `ContextEffect`, never `Effect`, whose constructor is `private[kernel]` (`kyo-kernel/shared/src/main/scala/kyo/kernel/Effect.scala:31`).
2. **Is it a new node, handler kind, or `Arrow`?** It cannot be. All three hierarchies are sealed and `private[kyo]`; compose from the existing nodes (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/KyoInternal.scala:18`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:12`, `kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:14`). `Mask` is the model for what a new capability looks like: two `handleCont` calls and no kernel change (`kyo-kernel/shared/src/main/scala/kyo/Mask.scala:28-36`).
3. **Does it touch the union?** Then discriminate `Kyo` first and defer, take the budget, unnest exactly once, and return the eval's currency (`kyo-kernel/shared/src/main/scala/kyo/kernel/Pending.scala:99-107`). Never cast in place of the lift where the payload can itself be a computation (`kyo-kernel/shared/src/main/scala/kyo/kernel/Loop.scala:242-245`).
4. **Does it add a stack entry?** Decide whether it is a `Step` (foldable) or a `Region` (must stay findable). A handler, binding, catching scope or finalizer is a `Region`, and folding it away silently breaks the scans (`kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:87-90`, `kyo-kernel/shared/src/main/scala/kyo/Arrow.scala:103-106`).
5. **Which handler variant?** `handleCont` for continuation-in-hand, `handleLoop` for stateless answers, `handleLoopState` for threaded state; add the `*With` form if the result feeds a known continuation; keep the `S`/`S2` row pair; override `answers` with the matching `Handler` template or lose the per-site answer loop silently (`kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:49-53`, `kyo-kernel/shared/src/main/scala/kyo/kernel/ArrowEffect.scala:121-126`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:411-413`).
6. **Which tag relation do you need?** Handlers match by subsumption, bindings by equality; erase the tag when the type parameter must not gate matching (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:230-233`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:222-224`, `kyo-prelude/shared/src/main/scala/kyo/Abort.scala:48`).
7. **Does it fork?** Then decide the isolate story: a `given isolate` for one obvious policy, no isolate at all for a short-circuiting effect, and nothing for a `ContextEffect`, which crosses through `Contextual` (`kyo-prelude/shared/src/main/scala/kyo/Check.scala:114`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:79-80`, `kyo-kernel/shared/src/main/scala/kyo/kernel/Isolate.scala:601-609`).
8. **Does it own a resource?** Releases run exactly once, a park carries them rather than running them, and a multi-shot clause over a bracket is refused with `Finalizer.Spent` (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Finalizer.scala:41-42`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:784-792`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Stack.scala:43-53`).
9. **Is it `inline` and public?** Then every symbol it names must be public at both levels, imported unqualified, non-`@static`, and it gets a case in `outsidekyo/KernelTest.scala` that compiles and runs it (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala:12-17`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Eval.scala:4-8`, `kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Nested.scala:11-14`, `kyo-kernel/shared/src/test/scala/outsidekyo/KernelTest.scala:17-21`).
10. **Is it platform-specific?** Then both `jvm-native/` and `js-wasm/` get a copy with an identical member surface and identical visibility, differing only where the platform forces it (`kyo-kernel/js-wasm/src/main/scala/kyo/kernel/internal/Safepoint.scala:22-25`).
11. **Is it a new internal class on the interpreter path?** Add it to `EffectTrace.isPlumbing` (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/EffectTrace.scala:125-136`).
12. **Are you conceding a module rule?** Write the four-part concession (measured justification, smallest scope, unreachable from user code, never the only copy) and pin its hostile axes in a section that says so (`kyo-kernel/shared/src/main/scala/kyo/kernel/internal/Handler.scala:32-42`, `kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1629-1633`).
13. **Tests.** Extend `kyo.Test`, assert concrete values through the public surface, drive parks with `SafepointStop.request()` and abandonment with `Eval.finalizeResources`, leave the safepoint slot as you found it, and put a cross-platform case in `shared/` unless it is genuinely not expressible or not portable there (`kyo-kernel/shared/src/test/scala/kyo/Test.scala:17`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointStop.scala:7-9`, `kyo-kernel/shared/src/test/scala/kyo/kernel/EffectTest.scala:727-729`, `kyo-kernel/shared/src/test/scala/kyo/kernel/ArrowEffectTest.scala:1983-1995`, `kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointUnstartedThreadTest.scala:6-8`).
14. **Did a pinned number move?** A bytecode size or a stack-safety depth that changed is a result to investigate, never a baseline to rewrite (`kyo-kernel/jvm/src/test/scala/kyo/kernel/ArrowEffectBytecodeTest.scala:7-10`).
