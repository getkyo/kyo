## 2. `EffectTraceTest.scala` (445 / 0), ported from main's `TraceTest.scala`

Main's `TraceTest`, `TracePoolTest` and `TracePoolConcurrencyTest` were deleted on this branch.
Their subject was `Trace` (a per-fiber ring of frames pushed by `Safepoint.pushFrame`, pooled by
`TracePool`, rendered by `Trace.render`). Here the same job is done by `EffectTrace`: on a throw the
evaluator walks the arrow/node graph and the region stack (`EffectTrace.attach` from `Eval` and
`Handler`), builds `StackTraceElement`s under a 64-frame budget (`maxTraceFrames`), hangs them on
the exception as a suppressed carrier, and splices them ahead of the physical trace
(`EffectTrace.splice`). There is no ring, no pool, and no render function.

| `"counts only consecutive repeats, not all occurrences"` (416) | `TraceTest` same-named case | `stepA, stepB, stepA` stays two runs of `stepA`. |

## 3. `SafepointConcurrencyTest.scala` (376 / 0), ported from main's `SafepointTest.scala`

the evaluator's per-thread slot in a static table (`kyo-kernel/jvm-native/src/main/scala/kyo/kernel/internal/Safepoint.scala`),
resolved by `Safepoint.get()`. The surviving subject of main's thread cases is which slot a thread
resolves.

### I did not create `kyo-kernel/jvm/src/test/scala/kyo/kernel/internal/SafepointTest.scala`

The brief told me to create main's path for slot-API cases. Doing so would break the build: this
branch already has `kyo.kernel.internal.SafepointTest` at
`kyo-kernel/jvm-native/src/test/scala/kyo/kernel/internal/SafepointTest.scala`, and `build.sbt`
adds `jvm-native/src/test/scala` to the JVM project's test sources (`project/TestKyo.scala` names
the same partially-shared roots). A second file at `jvm/src/test/scala/...` would define the same
class twice in `kyo-kernelJVM`. The existing jvm-native suite is that file under a different path,
and it already carries the slot API (stop/consumeStopped, slices, the enter/exit/save/restore
budget). It is not one of my assigned files, so the four thread-identity ports went into
`SafepointConcurrencyTest` instead; two of them (`"allows resuming in the same thread"`, `"no new
Safepoint for nested eval calls"`) are single-threaded and would sit more naturally in that
jvm-native suite if someone owns it later.

## Compile risk

I cannot run sbt, so nothing here is compiled against the kernel. I did check the isolated language
questions with a standalone `scala-cli` compile on Scala 3.8.4 under the build's flags
(`-language:strictEquality -Werror -Wvalue-discard -Wconf:...:error`, `-Wnonunit-statement` off as
`kyo-settings` does for `Test`): main's `implicitly[...]`-in-statement-position style, main's
`boundedMethod("hello")` against `A <: AnyVal`, `typeCheckErrors` on a type argument with an
unresolved name, opaque-type `==` under strictEquality and the `CanEqual` fix, and `@volatile` local
vars of an opaque type. Remaining risk, by edit:

1. `CanLiftTest extends Test` assumes `kyo.Test` is on the shared test classpath for this module
   (it is: `kyo-kernel/shared/src/test/scala/kyo/Test.scala`, and `IsolateTest` extends it).
2. `CanLiftTest` `"a kyo module object does not lift"` pins the macro message
   `"Cannot lift 'kyo.kernel.ArrowEffect$' to a 'ArrowEffect$ < S"`. The `$` suffixes follow main's
   own `AbortCombinatorsTest` assertion on the same macro; if this module symbol renders without
   them the case fails (red test, not a compile error).
3. `EffectTraceTest` `"repeated frames"` and `"counts only consecutive repeats"` assert on how many
   frames the walk records. I wrote them to be independent of how many times the walk visits the
   continuation: `Handler.ContHandler.answering` attaches with both the composed continuation and
   the suspension node, and the node re-walks `kyo.cont`, so a per-walk count can double. The
   assertions are "no two adjacent elements are equal" and "stepA occurrences are twice stepB's",
   which hold under either. If the walk shape differs from my reading of `EffectTrace.Builder`,
   these are the two cases that fail.
4. `EffectTraceTest` `"the carrier's message renders one at line per frame"` asserts
   `dropped == 0` for the small `outerStep` walk, so that the message has no trailing
   `... N more not walked` line. That follows from the budget (64) being far above what that walk
   records, but it is an assertion about a number I did not observe.
5. `EffectTraceTest` `"bug #1172 null frames"` calls `EffectTrace.attach` directly. `EffectTrace` is
   `private[kernel]` and the test is in `kyo.kernel.internal`, so access is fine; the case relies on
   `reconstruct`'s `catch case failure if NonFatal(failure)` swallowing the NPE from reading a null
   `Frame`, which is what main's #1172 case protected.
6. `SafepointConcurrencyTest`'s four ported cases assume a live thread's slot cannot be claimed by
   another live thread. That is what `Safepoint.resolve`'s `claim` does (it only takes a cell whose
   owner is null or dead), and the ported cases run before the two cases in the file that fill all
   65536 slots.
