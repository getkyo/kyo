## Not verified

**I did not compile either file.** The brief forbids running sbt, so nothing below is more than a
reading of the current sources.

Edits carrying compile risk, highest first:

1. `EffectTest` line 27 and line 38: main's `val effect = Effect.defer { ... }` is taken verbatim,
   with no type ascription, where every pre-existing case in this file ascribed `val d: Int < Any`.
   `<` is `opaque type <[+A, -S]` (`Pending.scala:43`) and `eval` is an extension on `A < Any`
   (`Pending.scala:398`), so an unconstrained contravariant `S` should instantiate to `Any` and
   `.eval` should resolve. Main compiles the same shape against the same variance. If anything in
   these two files fails to compile, this is the first place to look; the fix is a `: Int < Any`
   ascription on both.
2. `ContextEffectTest` line 41: bare `succeed`. `org.scalatest.Assertions.succeed` takes no
   arguments and other kernel suites here use it bare, so this should be fine.
3. `ContextEffectTest` lines 84-85 and 147-148: the wrapped type ascriptions. Both halves are inside
   140 columns and `newlines.source = keep`, so scalafmt should leave them; if it reflows them the
   result is cosmetic, not a failure.
4. The eleven `handle` -> `handleInheritable` renames: the target overloads
   (`ContextEffect.scala:151`, `:172`) have the same clause structure as main's, so the inference of
   `_ + 1`, `_ * 2`, `!_`, `_.toUpperCase` should behave as it does on main.
5. The two wildcard imports and the name `Arrow`. `kyo.*` and `kyo.kernel.*` are wildcards of equal
   precedence, so a name reachable through both must resolve to one symbol or the reference is
   ambiguous. `Loop` is exactly that shape (`val Loop = kernel.Loop` in `kyo/kernel.scala:5`, plus
   `object Loop` in `kyo/kernel/Loop.scala:28`), and main's own `ArrowEffectTest.scala` is in
   `package kyo.kernel`, carries both wildcards, and calls `Loop.continue` unqualified, so that
   shape is proven to compile. `Arrow` is the one case main cannot vouch for: `export kernel.Arrow`
   in `kyo/kernel.scala` is marked "Not on main", so this kernel is the first to reach `Arrow`
   through both wildcards. The export forwarder should dealias to `kernel.Arrow` and resolve the
   same way `Loop` does. If it does not, the symptom is an ambiguous-reference error on `Arrow` in
   both files, and the fix is one line: `import kyo.Arrow`, which is a non-wildcard import and
   outranks both wildcards. `discard` is not at risk; it is defined only in package `kyo`
   (`kyo-data/shared/src/main/scala/kyo/data.scala:8`).

Nothing else is unresolved. I touched only my two assigned files, ran no build, made no commit, and
did not go near `EffectBracketTest.scala`.
