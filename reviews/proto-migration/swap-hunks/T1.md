## Main cases omitted

All four depend on `Safepoint.Interceptor` / `Safepoint.immediate` / `Safepoint.eval`, which this
kernel removed by design (Safepoint here is the evaluator's stack-depth slot and has no interceptor
API and no way to deny an entry).

- `handleFirst > defers when the safepoint denies entry and completes on evaluation`
- `handle.catching > failure when the safepoint defers the handler`
- `handle.catching > success when the safepoint defers the handler`
- `handlePartial > drains a deferred handler continuation`

`denyOnce()`, the interceptor fixture those four cases share, is removed with them.

The behaviour they wrap (deferral of the handler, then completion at evaluation) is not lost: in this
kernel every handler is a lazy node by construction, which `handleCont > lazy: the handled computation
is a value and answers at eval` and the `Eval.partial` cases pin directly.

## Divergence comments added

Four `// Diverges from main:` comments, each above the case or group it explains.

- 127-128, `handle > execution is tail-recursive`: the property main pins is that execution is
  tail-recursive, and it holds; only main's constant is off. `maxDepth - minDepth` is a flat 12 over
  10000 iterations here, because the first `loop` call runs from the test body and every later one
  runs inside the evaluator, whose frames between the two are a constant. Main's inline handling added
  at most 10. Main's text is unchanged and only the expectation moved, to `<= 20`: a generous bound
  keeps the intent (a non-tail-recursive run would be in the thousands) without pinning the exact
  frame count. Reported by the suite run, see "Verification" below.
- 329-331, `handlePartial`: `handlePartial` is gone; `Eval.partial` over an already-closed region is
  the partial-evaluation entry point, and the stop condition is the safepoint's rather than a flag
  handed to the handler.
- 385-387, `nested effects handling`: `Nested` here is a plain box, not a suspension node, so a
  handler's settled path unnests it and the `done` arm re-boxes. Main asserts `result == nested` on a
  `Nested` case class; here the wrapper read back is a fresh instance, so each case asserts on the
  computation it carries (`Nested.unnest[Any](result) eq comp`) instead. No assertion was dropped:
  the box-crossing property main checks is exactly what these still check.
- 428-429, `handleFirst on Nested`: the region is a node here, so its answer is observable at `eval`
  and not at `evalNow`; the standing row is closed to read it.

reported the result.

- One failure: `handle > execution is tail-recursive`, `12 was not less than or equal to 10`, main's
  constant being wrong for this evaluator rather than the property failing. Fixed by restating the
  bound to `<= 20` with the divergence comment above; main's case text is otherwise unchanged.
- Everything else in this file compiled and passed in that run.
- The restated bound itself has not been re-run since the edit. It is the same case, loosened from 10
  to 20 against a measured constant 12, so it should pass, but nobody has watched it pass yet.

The concerns I flagged before that run are now settled by it: the imports compile, the
`handleFirst` result-type annotations are enough for inference, `Kyo.lift` at generic positions
works, and `handlePartial > respects the stop condition` behaves as read from `Eval.scala:29-36`.

For the record, what those edits were and why.

1. **Imports (hunk 1).** I took main's `import kyo.*` and `import kyo.kernel.internal.*` and dropped
   the 15 single-name `kyo.*` imports the previous file had, but I deliberately did **not** take
   main's third line, `import kyo.kernel.*`. This kernel exports `Arrow` at the `kyo` level
   (`kernel.scala`, "Not on main: the continuation type is public here"), so `kyo.*` and
   `kyo.kernel.*` would both offer `Arrow` (and `Isolate`) as wildcard imports of different symbols,
   which is an ambiguous reference; main never hits it because main does not export `Arrow`. With
   only `kyo.*`, `Arrow`, `Isolate` and `Loop` resolve through the wildcard and `ArrowEffect`,
   `ContextEffect` and `Effect` through the enclosing package. `Absent` and `Present`, previously
   imported as `kyo.Maybe.Absent` / `kyo.Maybe.Present`, now come from the top-level exports in
   `kyo-data/.../Maybe.scala:14-15`.
2. **`handlePartial > respects the stop condition` (349).** It calls `requestStop()` (the file's own
   helper, which sets both the JVM/Native stop slot and the JS/Wasm deadline) before `Eval.partial`,
   relying on `Eval.partial` consuming an already-set stop and returning its input untouched
   (`Eval.scala:29-36`), which also clears the flag so it cannot leak into the next case.
3. **`handleFirst` result-type annotations (142, 162, 178, 196).** Main writes these calls
   unannotated. Here `handleFirst` has two type parameters (`B`, `S2`) that only the polymorphic
   clause could fix, and every pre-existing raw `handleFirst` call in this file carries an expected
   type for exactly that reason, so I annotated the four ported calls the same way.
4. **`Kyo.lift` at generic positions** in the `nested effects handling` helpers. `kyo-kernel/CONTRIBUTING.md:102`
   states this is the supported shape (it is how `Isolate.nest` re-nests), and the previous version
   of this file already used `Kyo.lift` on concrete pending values.

Nothing else was touched: no other file was edited, no build was run, no commit was made.
