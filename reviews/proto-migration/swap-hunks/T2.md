## Main cases omitted

None. Every leaf in main's `PendingTest` is in the file.

Two adaptations are worth the coordinator's eye because the behaviour they pin is not identical to main's:

1. `evalNow / accepts nested computations`. Main wraps the body in `Safepoint.eval` so the enclosing
   fiber's preemption interceptor cannot defer `TestEffect.run`'s inline handling, and then asserts
   `TestEffect.run(v).evalNow` is `Present(2)`. This kernel has no interceptors and does not apply handling
   eagerly, so the handled computation is `Absent` until it is run. The ported case keeps main's structure
   and asserts `TestEffect.run(v).evalNow == Absent` and `TestEffect.run(v).eval == 2`. Those are exactly
   the two assertions our previous `evalNow accepts nested computations` made against a local effect, so
   the expected values are measured, not guessed. The divergence carries a `// Diverges from main:` note.
2. The three deferral cases. Main's `denyNestedResumption` is a stateful interceptor that denies entry into
   the *second* pending computation only. `drainedBudget` denies *every* entry inside the block, because the
   budget is the only denial mechanism this kernel has. The final-value assertions are main's and unchanged,
   but the deferral is no longer aimed at one specific resumption. The six budget cases appended after them
   (hunk 20) cover map, flatMap, flatten, andThen, unit and the doubly-nested strip under the same mechanism.

## Bytecode pins: main's `BytecodeTest` versus our two suites

Main's `BytecodeTest.scala` has four pin cases. Every expansion site it pins is pinned here. There is
nothing to hand back for measurement.

| main case | main's method shape | main's pin | pinned here as | our pin |
|---|---|---|---|---|
| `suspend` | `class TestSuspend { def test() = ArrowEffect.suspend[Int](Tag[TestEffect.type], 42) }` | `test -> 16` | `ArrowEffectBytecodeTest / suspend`, identical fixture | `test -> 14` |
| `suspendWith` | `class TestSuspendMap { def test() = ArrowEffect.suspendWith[Int](Tag[TestEffect.type], 42)(_ + 1) }` | `test -> 16` | `ArrowEffectBytecodeTest / suspendWith`, identical fixture | `test -> 14` |
| `map` | `class TestMap { def test(v: Int < TestEffect.type) = v.map(_ + 1) }` | `test -> 26, anonfun -> 8, mapLoop -> 151` | `PendingBytecodeTest / map`, identical fixture | `test -> 18, run -> 95` |
| `handle` | `class TestHandle { def test(v: Int < TestEffect.type) = ArrowEffect.handle(tag, v)([C] => (input, cont) => cont(input)) }` | `test -> 26, anonfun -> 8, handleLoop -> 283` | `ArrowEffectBytecodeTest / handleCont`, the same site under the renamed API | `test -> 48` |

The assertions compare the whole method-size map with `==`, so the set of generated methods is pinned too,
not just the sizes. That is why our `map` pin naming `run` rather than `mapLoop` and `anonfun` is a complete
pin of the same site rather than a partial one.

No pinned number was changed and no new numeric pin was added.

The one edit I made in these files: `ArrowEffectBytecodeTest`'s fixture class `TestSuspendWith` is renamed
back to main's `TestSuspendMap`. The class name is not a design divergence and does not enter the pinned map
(which is keyed by method name), so the rename is measurement-neutral and removes two lines of diff. Main's
name is stale relative to the `suspendWith` API it exercises, so if the coordinator prefers the clearer name
this is the one line to revert.

Deviations left in place in the bytecode suites, with reasons:

- `extends AnyFreeSpec` rather than `kyo.test.Test[Any]`: the module-wide divergence recorded in `build.sbt`.
- Explicit imports rather than `import kyo.*`: the convention every kernel suite in this branch follows.
- `TestHandleCont` / the `handleCont` case name: forced by the API rename.
- `TestHandleCont` passes the `done` argument (`a => a`) that main's `handle` did not need. Removing it to
  match main's text would change the measured bytecode, so the pinned `test -> 48` requires it to stay.
- `val sizes` plus `assert(sizes == Map(...), sizes.toString)` rather than main's `val map` and a bare
  `assert`: the clue argument reports the actual sizes when a pin breaks. This is strictly more information
  than main's form, so I did not revert it.
- `private` on the two helper methods, which main leaves public. Each suite carries its own copy now, so
  they are genuinely local.

## Compile risk

I cannot typecheck. These are the edits where a compile error is plausible, in descending order of concern:

1. `class PendingTest extends Test` (`kyo.Test`, which mixes in `NonImplicitAssertions`) is new for this
   file, and it is what makes main's `typeCheckFailure(code)(expected)` calls port verbatim. Precedent:
   `IsolateTest` and `KyoTest` in this branch both extend it. The file still uses `assertTypeError`, `fail()`
   and plain `assert`, all of which `NonImplicitAssertions` leaves intact.
2. `TestEffect.run` is main's exact text apart from `handle` to `handleCont`, which means the one-argument
   `handleCont` overload with an inferred result type, leaving `S2` unconstrained. The one-argument overload
   is used with an explicit result type in `KyoForeachTest` and `ArrowEffectMaskTest`; an inferred result
   type is used with the two-argument overload in this file's previous local `run`. The combination of both
   is not precedented in the branch. If it fails to infer, the fix is one token: annotate `: A < S`.
3. Main's eta-expansion spellings restored in the nested group and the handle group:
   `comp.map(_.handle(TestEffect2.run))`, `nested.map(v => Kyo.lift(v.handle(TestEffect1.run)))` and
   `TestEffect(1).handle(TestEffect.run)`. The last eta-expands a polymorphic method with a by-name
   parameter. `_.handle(TestEffect2.run)` already appears in our previous `andThen on nested`, so the shape
   itself compiles here.
4. Six compiler-message pins ported from main. `ImplicitsTest` in this branch already pins
   `Required: Any < Any`, `Required: Int < Any < Any` and `Required: Int => String < Any < Any` against this
   kernel, and `KyoTest` pins `value eval is not a member of Int < ...`, so all six are message shapes this
   kernel is known to produce. If one differs, the failure is a test failure, not a compile error.
5. `nested computations / unit` is main's text verbatim, which means it declares `val comp3` and then
   asserts `comp2.eval` a second time rather than `comp3.eval`. That looks like a copy-paste slip in main:
   `comp3` is never read, so its shape is never checked. I did not change it, because changing it would put
   a non-divergence hunk in the diff. Our previous file had dropped `comp3` entirely. If you want the slip
   fixed, the change is `comp2` to `comp3` on that one line, and it strengthens the case.
6. `-Wunused` is not in `compilerOptions`, so the unused `comp3`, the unused lambda parameter in
   `works with functions that return effects` and the two `@nowarn("msg=unused")` annotations that may now
   suppress nothing are all warning-free under `-Werror`. This is inference from the build settings, not
   from a compile.
